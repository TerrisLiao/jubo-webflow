## C. 實作方式

| 需求 | 做法 |
|---|---|
| 強制換行 | 文字節點插入 line break（`<br>`），不新增 class |
| 不可斷開 | section 限定 combo 加 `white-space: nowrap`，或調整容器寬度；**不得**改共用 `jp3-*`、utility、variable |
| 左對齊 | section 限定 combo 覆寫 `text-align`；不改共用 `jp3-body` |

強制換行在窄斷點可能造成不理想的折行，四斷點（Desktop／Tablet／Mobile landscape／Mobile portrait）都要實測。

## H. 換行修正（2026-09-15，第二輪）

### H1 錯誤與原因

G 章用「在文字節點寫入換行字元（`\n`）」的方式做斷行，**全部沒有生效**。
Webflow 的文字節點輸出的是一般 HTML 文字，`\n` 被當成一般空白折疊掉，不會變成 `<br>`。
Terris 提供截圖後才發現：團隊標題、關於我們標題、Hero 內文、解決方案導言、Manifesto、
About us 日本市場標題與 CEO bio 的斷行都沒有出現。

**同時暴露的驗證缺口**：G4 只用 `query_elements` 回讀文字，證明的是「字串存進去了」，
不是「畫面會斷行」。字串寫入成功 ≠ 視覺結果正確，之後不可再用回讀當作斷行的驗收證據。

### H2 修正做法

新增 class **`is-jp-preline`**（`white-space: pre-line`），套在**擁有換行字元的那個元素**上，
讓既有的 `\n` 真正渲染成換行。

- 未修改任何既有共用 class；`is-jp-preline` 是新建的。
- 多 class 元素一律以 **combo** 形式建立（`.jp-about_h2.is-jp-preline` 等），
  避免污染 base class。`set_style` 會覆蓋整個 class 陣列，套用時已把原有 class 一併帶回。

建立的 combo：

| 選擇器 | 用途 |
|---|---|
| `.is-jp-preline`（單獨） | 無 class 的 span：團隊標題次段、資安標題次段 |
| `.text-align-center.is-jp-preline` | Overview Manifesto H2 |
| `.jp3-body.jp-solutions_lead.is-jp-preline` | 解決方案導言 |
| `.jp-partner_hero-lead.is-jp-preline` | Overview Hero 內文 |
| `.jp-about-jubo_intro.is-jp-preline` | 關於我們內文 |
| `.gradient-headline.is-jp-preline` | 關於我們 H2 漸層 span |
| `.jp-about_leader-bio.is-jp-preline` | About us CEO bio |
| `.jp-about_h2.is-jp-preline` | About us 日本市場標題 |
| `.jp-about_body.is-jp-preline` | About us 日本市場導言 |

同時補上原本漏做的一處：Overview「關於我們」H2 的 `Juboについて` 與

### K11 兩個關鍵修正（2026-09-15）

Terris 以實機回報「標題沒置中」「分段難看」後查出兩個根因，其中第二個是先前調整無效的主因。

#### 根因 1：標題置中是靠 flex，不是 text-align

`.section-header_wrapper` 使用 `display:flex; flex-direction:column; align-items:center`。
這會把 h2 的**盒子**置中，但盒子內各行的對齊仍由 `text-align` 決定，
而 `.jp-about_h2` 未設定 `text-align` → 預設 `left`。

桌機標題只有 1–2 行、盒子接近滿版，看起來像置中；手機折成 4 行後，
盒子寬度縮為最長那行，其餘行靠左貼齊，破綻才顯現。**非本次改動造成，但被字級調整放大。**

修正：`.jp-about_h2` 於 `small` 與 `tiny` 補上 `text-align: center`。

#### 根因 2：`tiny` 斷點既有覆寫，使所有 `small` 調整在直式手機失效

| Class | tiny 既有值 | 後果 |
|---|---|---|
| `.jp-about_h2` | `font-size: 2.1rem` | 覆蓋 small，實機仍為 33.6px |
| `.jp3-h2` | `font-size: 2.1rem` | 同上 |

Webflow 斷點由大往小繼承，**`tiny`（≤479px）覆蓋 `small`（≤767px）**。
直式手機落在 `tiny`，因此 K1、K6、K8 寫在 `small` 的字級對這兩個 class **完全沒有生效**。

`11 字 × 33.6px ≈ 370px`，正好是實機截圖中「台湾の介護現場で培った」11 字後換行的原因。

修正：改寫入 `tiny` 斷點。

| Class | tiny 新值 |
|---|---|
| `.jp-about_h2` | `1.5rem` / `1.4` / `text-wrap: pretty` / `text-align: center` |
| `.jp3-h2` | `1.625rem` / `1.35` |

未受影響（無 tiny 覆寫，`small` 值正常生效）：`.jp-journey_heading`、`.jp-security_heading`、
`.text-align-center.is-jp-preline`、`.text-align-center.is-jp-hero-copy`、`.page-wrapper.page-jp`。

#### 連帶更正：Designer 快照畫布其實是 `tiny`

K7／K8 稱快照畫布 351px「比實機窄」是對的，但更關鍵的是
**351px < 479px，落在 `tiny` 斷點**。先前多次「改了 small 卻看不到變化」，
原因不是快照延遲，而是畫布本來就在套 `tiny`。

**往後規則：調日文頁手機版一律先查該 class 有無 `tiny` 覆寫，並優先寫入 `tiny`。**
