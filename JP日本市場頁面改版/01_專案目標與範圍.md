# 01 專案目標與範圍

## 背景

`/jp/company` 於 2026-08-19 更名為 `/jp/about-us`（slug `company` → `about-us`）。
該頁從未發布過，沒有 SEO 或外部連結風險。

改版起點的實況（透過 Webflow MCP 逐項查證，比最初的交接描述更空）：
component 實例 0 個、Image 元素 0 個、`main-wrapper` 的 tag 是 `div` 而非 `main`、
29 個元素掛 legacy 的 `jp3-*`、section 命名重複且語意不成立。
換句話說當時的問題不是「排版不佳」，而是**尚未套用設計系統**。

## 目標與受眾

**about-us 的定位是「会社概要」——公司基本資訊揭露，不是行銷頁。**

- 主要受眾：**代理商與合作夥伴**，不是終端買家。
- 想接洽合作 → 走頁內的日本市場詢問表單。
- **想購買產品 → 一律導向 MDX**（日本市場合作夥伴）。
- 因此頁面追求「可掃讀、可查證」，不追求設計感與敘事張力。

**overview 的定位是產品與能力介紹**，維持既有的產品導向敘事，
公司信用資料不併入（理由見 `03_設計決策紀錄.md`）。

## 範圍

- Webflow Draft 頁面 `/jp/about-us` 與 `/jp/overview`，以及兩頁之間的導線。
- 網站本體在 Webflow 雲端；本 repo 是規範與交接資料，**不是網站原始碼**。

## 不可違反的規則

> 這一節是本專案的鐵律，與 [`../Jubo官網AI開發規範/00_AI工作守則.md`](../Jubo官網AI開發規範/00_AI工作守則.md) 併行適用。

1. **不發布。** 兩頁維持 `draft: true`。
2. **Client-First 結構**：`page-wrapper > main-wrapper > section_* > padding-global + padding-section-* > container-*`。既有 `all-sections-wrapper` 可保留。
3. **不修改 Component definition、utility class 或 variables**（會影響全站）。
4. **不用自訂 CSS／HTML 做版面。** 唯一允許的 HtmlEmbed 是手寫簽名動畫與 Jubo 字標 SVG，程式碼原樣複用。
5. **不可 rename 既有 class** —— class 是站台全域的，改名會動到已發布頁面。要改命名時用「複製屬性到新 class 再改掛」。
6. **Slater 鎖定的 class 一律原名沿用**（見 [`../custom-code/slater-selectors.md`](../custom-code/slater-selectors.md)）。這些 class 由外部 JS 以選擇器驅動，改名等於功能失效。
7. **新 custom class 用 `folder_element` 命名，變體用 `is-*`**，單一元素最多四個 class。新頁不再擴充 `jp3-*`、`jp-partner-*` 等 legacy 命名。
8. 色彩、間距、圓角**優先使用 Webflow variables**，避免硬寫 hex 或 px。
9. **四個斷點都要處理**：main、medium、small、tiny。
10. 所有新增文字先用繁體中文；**日文由日文老師校稿後才替換**。

## 完成定義

只有下列條件同時成立，才可回報「結構完成」：

1. about-us 讀起來像日本企業網站的**可查證資料頁**，不是行銷卡片牆。
2. 兩頁導線雙向且經過讀回驗證（不能只看 API 回報成功）。
3. 四個斷點都無水平 overflow、文字截斷、重疊或不合理留白。
4. heading 層級連續，且每頁**恰有一個 h1**。
5. 未污染全站共用樣式（component／utility／variable 未被修改）。
6. 兩頁仍是 Draft。

> 文案是否「完成」不在此定義內 —— 文案潤飾由 Codex 另行處理，
