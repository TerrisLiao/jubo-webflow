## 第三階段：經營團隊卡片的多輪視覺迭代

這一段來回最多，最終收斂結果與理由見 `03_設計決策紀錄.md` 第 4 節。過程摘要：

2×2 玻璃疊層卡 → 縮小照片／拉長版面 → **修正誤解**（玻璃卡應疊在照片內，不是把照片切小露底色）
→ 修掉照片底部露灰的 bug（`<img>` 缺 `height:100%`）＋卡片比例對齊照片原始比例 2:3
→ 試做白色留白外框（**否決**）→ 試做玻璃質感外框（**否決**）→ 回到滿版
→ 玻璃面板改固定高度使四卡頂齊 → 間距修正（縮小責任從卡片移到網格）
→ 加入 2×2 階梯錯落排版 → 字級與顏色微調

> 中間一度把「間距太遠」誤判成 gap 值問題，實際根因是卡片自己置中留白疊加 gap。

## 2026-09-07 — 修正 Overview 創辦人區 eyebrow 手機版被擋住

- 現象：`/jp/overview` 創辦人／CEO 段落的 eyebrow 標籤「創業者・CEO」在手機版視覺上緊貼在照片下緣，看起來像被照片擋住；桌面版（照片與內容欄左右並排）正常。
- 根因：eyebrow 是 `jp-ceo_content` 欄位的第一個子元素，與 H2 標題綁在一起。桌面版兩欄並排時在內容欄最上方沒有問題；手機版單欄堆疊後，內容欄整塊接在照片正下方，eyebrow 因此貼著照片下緣，間距不足。
- 處理前發現 Designer 裡有一份未發布草稿，已把 eyebrow 搬出 `jp-ceo_content`、變成整個 grid 最上方的獨立標籤，且手機版 grid 一併改成 `flex` 並加上 `order`。經 Terris 確認**不是他本人的進行中修改**，予以還原（eyebrow 移回 `jp-ceo_content` 第一個子元素；`jp-ceo_grid`／`jp-ceo_portrait`／`jp-ceo_content` 的 `small` 斷點還原成與目前已發布版一致）。
- 修法：不動 DOM 結構、不動任何共用 class 的既有數值。新增 combo class `jp-ceo_eyebrow`（掛在既有 `section_tag.text-size-tiny.is-eyebrow` 之後，即 `.section_tag.text-size-tiny.is-eyebrow.jp-ceo_eyebrow`），只在 `small`（≤767px）斷點設定 `margin-top: 2rem`；`main`／`medium` 無任何屬性，桌面版與平板完全不受影響。
- 驗證限制：本輪透過 MCP 讀回四斷點 style 與已發布 CDN CSS 比對確認結構與數值正確；但此環境的無頭瀏覽器無法連上 jubo-health.com（sandbox 代理限制），**未能實際截圖手機版驗證視覺結果**，仍待人工在真機或 DevTools 手機模式覆核。
- 未 Publish；本次也未動到 `jp-ceo_grid`／`jp-ceo_portrait`／`jp-ceo_content` 的既有數值（只還原了非發布狀態的暫留修改）。

### 同日追加：Terris 指出手機版順序不合邏輯，改為「eyebrow → 照片 → 內容」

- Terris 回饋：手機版應該是 eyebrow 標籤在照片「上面」（先看到標籤再看到照片），不是照片先出現。
- 做法（僅 `small` ≤767px 斷點，`main`／`medium` 完全未動）：
  - `jp-ceo_content` 在 `small` 加 `display: contents`，讓它底下的 eyebrow／H2／H3／兩段文案在手機版「攤平」成 `jp-ceo_grid` 的直接 flex 子層，藉此讓 eyebrow 可以脫離內容欄跳到照片前面。
  - `jp-ceo_grid` 在 `small` 改成 `display:flex; flex-direction:column; align-items:stretch`（取代原本繼承的 `grid`／`align-items:center`，`stretch` 是必要的，否則攤平後的標題與內文會縮成置中窄欄）。
  - `jp-ceo_eyebrow`（前次新增的 combo class）在 `small` 移除先前的 `margin-top:2rem`，改設 `order:-1`（讓它排到最前面）＋`margin-bottom:2rem`（與照片保持間距）。
  - 最終手機版視覺順序：eyebrow → 照片 → H2 → H3（姓名）→ 兩段文案，符合「先看到標籤、再看到人、再看到內容」的邏輯。
- 已知取捨：`display:contents` 拆散後，H2/H3/兩段文案彼此的間距在手機版改由各自既有的 margin 相加而成（flex 子項的 margin 不會像原本 block 排版一樣互相 collapse），可能比原本略寬一點；`jp-ceo_content` 原本的 `max-width:650px` 在手機寬度本來就用不到（容器本身更窄），拆散後也不影響。若日後看實機發現內文間距不順，可再個別微調。
- 驗證限制同前：sandbox 內無頭瀏覽器無法連上 jubo-health.com，這次的排序與間距只透過樣式規則推導確認，**未實機截圖驗證**，待人工在手機或 DevTools 手機模式覆核。

## 2026-09-07 — 修正 About-Us 各 section 之間的白邊

- 現象：Terris 回報 About-Us 頁面「公司概要」段落底部（據點／JuboLink for Dental／お問い合わせ先幾列）跟下一個 section 交界處出現一條不該有的純白色橫帶，截斷了原本連續的淡藍漸層背景。
- 根因（全站共用 class 的既有 bug，非本次新增）：全站標準結構 combo `padding-global.padding-section-large` 目前帶有 `margin-bottom: -124px`，已經發布上線、且違反 Client-First 規範本身（`padding-section-*` 只能管上下 padding，不該有 margin）。這個負值把 section 內層 wrapper 往上拉 124px，讓 section 自己算出來的高度比實際內容矮 124px，最後一段內容因此溢出到 section 的底色範圍外，露出後面沒有任何背景覆蓋的純白色。
- 影響範圍確認：`.padding-global.padding-section-large` 是全站共用的核心結構 utility，About-Us 頁面 5 個 section 裡有 4 個（公司概要、經營團隊、為什麼是日本、詢問表單；Hero 用的是另一套 `product-hero_*` 結構，不受影響）都套用同一個 combo，理論上全部都有一樣的白邊問題，不是只有截圖裡那一處。
- 已跟 Terris 確認**不直接改全站共用的 `padding-global.padding-section-large`**（怕影響其他頁面用到同一組合、可能原本靠這個負值遮住某處的溢出裝飾圖），改為**只在 About-Us 頁面單頁修正**。
- 修法：新增 combo class `jp-about_padding-fix`（掛在 `padding-global.padding-section-large` 之後），只設定 `margin-bottom: 0px`，蓋掉共用 class 的 -124px。套用在 About-Us 頁面全部 4 個 section 的 padding wrapper 上；未修改 `padding-global.padding-section-large` 本身的任何數值，其他頁面完全不受影響。
- 待辦：全站其他頁面若也用到 `padding-global.padding-section-large`，理論上也有同樣的白邊問題，但依 Terris 指示本次不處理，只記錄在這裡，之後若要全站修正需另外評估影響範圍再動手。
- 驗證限制同前：sandbox 內無頭瀏覽器無法連上 jubo-health.com，本次修法透過讀回已發布 CDN CSS 確認 `-124px` 確實存在、且新 combo 的 CSS 值正確蓋過舊值，但**未能實機截圖驗證白邊是否真的消失**，待人工在瀏覽器覆核。

### 同日追加：Terris 確認其他頁面也有同樣白邊，改為全站直接修正

- Terris 自行檢查後確認：全站其他頁面確實也出現同樣的白邊，於是指示改成直接修正共用 class，不要只留在 About-Us 單頁 patch。
- 處理：
  - 直接從共用 combo `padding-global.padding-section-large` 移除 `margin-top: 0`、`margin-bottom: -124px`、`display: block` 三個屬性。這三個屬性違反 Client-First 規範（`padding-section-*` 只該有上下 padding），移除後這個 combo 的 `base` 已淨空，實際 padding 值完全交回單一 class `.padding-section-large`（桌面 8rem／平板 6rem／手機 4rem）與 combo 自己在 `medium`／`small` 的既有覆寫（平板 5rem／手機 3rem，兩者皆保留未動）。
  - `margin-top: 0px` 與 `display: block` 本身是無效值（div 預設就是 block、0 margin 不影響版面），移除後計算結果不變，純粹符合規範，不是視覺改動。
  - About-Us 頁面先前新增的單頁 patch class `jp-about_padding-fix` 已從 4 個 section 的 padding wrapper 卸除，並刪除該 style 定義，避免留下用不到的孤兒 class。
- 影響範圍：全站每一個使用 `padding-global.padding-section-large` 的 section 都會拿掉那 124px 的意外遮擋，理論上等於全站修好同一個白邊問題；未逐一巡查全站頁面確認每一處視覺結果，仍待人工抽查幾個代表頁面（首頁、其他 landing page）確認沒有頁面原本刻意依賴這個負值遮住溢出裝飾圖。
- 意外收穫：這次順便確認了 `14_Webflow_Agent_Instructions同步規範.md` §4-4(a) 待辦 2 的懸案——combo `.padding-global.padding-section-large` 在 `medium`／`small` 確實各自有 5rem／3rem 的獨立覆寫值，跟單一 class `.padding-section-large` 的 6rem／4rem 不同，兩者並存、都不是錯誤，只是不同層級的 class。
- 驗證限制同前：無法用無頭瀏覽器截圖驗證，僅透過 MCP 讀回樣式規則確認新舊值正確替換，實際視覺仍待人工覆核。
