### 兩個版本的取捨

在此之前 codex 已經做過一版：`.jp-back-to-top`，寫在 **Page Settings → Custom Code → Footer**，
是 `position: fixed` 右下角、深青色實心圓、捲動超過 0.75 個視窗高才淡入的浮動鈕，附帶自己的 CSS 與 JS。
Terris 決議移除它，改用頁尾常駐的 glass 版本。移除原因（不只是偏好問題）：

- 違反鐵律 4：自訂 CSS、手打色碼（`#0b8793` / `#006f82`）、手打 px，且完全不走 Webflow 樣式系統。
- 深青色實心圓不是站上任何按鈕的語彙；站上的按鈕語彙是 glass ＋漸層箭頭。
- 寫在 page custom code 裡 → Designer 看不到、元素樹讀不到、MCP 的 `query_elements` 也查不到，
  後續維護者很難發現它存在（見 `06` §11）。

原始程式碼存放在 `custom-code/archive/jp-about-us_page-footer_back-to-top_2026-09-08.html`，
需要時可還原，但復用前要先處理上述三點。

### 現行設計

```
section_about
└ padding-global padding-section-small
  └ container-large
    └ jp-about_to-top-wrap                 flex 置中
      └ glass-button                       a，aria-label，#page-top
        └ glass-element is-to-top          4.5rem（72px）圓形玻璃
          └ jp-about_to-top-icons          rotate(-90deg)
            ├ gradient-icon is-1 is-to-top 1.75rem 漸層箭頭
            └ gradient-icon is-2 is-to-top 1.75rem 漸層箭頭（hover 時滑入）
```

- **玻璃配方沿用本頁 `jp-about_leader-glass`**（領導團隊卡片）：
  `linear-gradient(135deg, rgba(255,255,255,0.82), rgba(225,235,250,0.62))` ＋
  `backdrop-filter: blur(40px) saturate(190%)` ＋ 1px 白邊，再加一層外陰影
  `0 12px 32px rgba(18,34,36,0.12)` 與內側高光 `inset 0 1px 0 rgba(255,255,255,0.85)` 撐出立體感。
  同一頁用同一套玻璃，不另創語彙。
- **第一版用 `glass-effect is-icon` ＋ 7 層 `glass-effect__* is-icon` 材質層，已拆掉。**
  原因：`.glass-effect__fill.is-icon` 是 `#f7f7f7cc`（近乎不透明的淺灰），
  疊起來的結果是一顆灰色圓盤，`backdrop-filter` 完全看不出來 —— Terris 回報「玻璃太不明顯」就是這個。
  那套材質層是為站上 CTA 裡 28px 的小箭頭徽章調的，放大到 72px 不成立。
- 形狀是圓形而非膠囊：`glass-element` 基底已有 `border-radius: 50em`，combo 只給正方尺寸並把基底
  `padding` 歸零，就自然是圓形。72px ≥ 44px 觸控目標。
- 箭頭是站上 CTA 用的同一顆漸層箭頭 SVG（`#00B2C0` → `#3B58FF` 72%），沒有另外畫圖。

### 為什麼箭頭朝上是靠旋轉，而且旋轉掛在內層 wrapper

Slater CSS（`slater.app/20018/60294.css`）用 `!important` 鎖住兩顆箭頭的 transform：

```css
.gradient-icon.is-1 { transform: translateX(0%) scale(1) !important; }
.glass-button:hover .gradient-icon.is-1 { transform: translateX(150%) scale(0.5) !important; }
.gradient-icon.is-2 { transform: translateX(-150%) scale(0.5) !important; }
.glass-button:hover .gradient-icon.is-2 { transform: translateX(0%) scale(1) !important; }
```

箭頭自己的 `transform` 完全不能動，所以改成**旋轉容器**：旋轉 -90° 之後右向箭頭在畫面上朝正上方，
而 Slater 的 `translateX` 也跟著變成「往上滑出、下一顆從下方滑入」，剛好是回到頁首該有的動態。

旋轉掛在 `jp-about_to-top-icons`（只包兩顆箭頭）而**不是**掛在 `glass-element is-to-top` 上：
玻璃的漸層與內側高光有方向性，整顆膠囊轉 -90° 會讓光源從左下角來，看起來不對。
把旋轉限制在箭頭層，玻璃就維持正常方位（光從左上），也能跟本頁 leader 卡片的 135° 漸層完全一致。

### `.gradient-icon.is-2.is-to-top` 為什麼必須存在

`.gradient-icon.is-2` 是 `position: absolute; left: 5px`，那個 5px 是為站上 `1.75rem` 小膠囊算好的
（(28 − 18) / 2 = 5）。放進 72px 圓形會偏左，hover 時第二顆箭頭會歪掉。
因此 combo 覆寫 `left: calc(50% - 0.875rem)`（0.875rem = 放大後 28px 箭頭的一半）拉回中央。
**不可以改 `.gradient-icon.is-2` 本身的 `left`** —— 那是全站共用值。

> 注意：站上 CSS 在 767px 以下有 `.gradient-icon.is-2 { display: none }`，
> 所以手機版只有一顆箭頭、沒有滑入滑出。這是站上既有行為，不是這顆按鈕的問題（觸控本來也沒有 hover）。

### 為什麼沒有直接插 Glass Button component

`04_素材與識別碼.md` 的原則是「按鈕直接用 Glass Button component，不要手刻」。這次是例外，原因是：

1. 該 component 只有 base 一個 variant、兩個 props（`CTA Text`／`CTA Links`），**一定會帶文字**，
   而這顆按鈕要的是「中間一顆漸層箭頭」的圖示型按鈕。
2. 它有 105 個實例，改 component definition 會影響全站（違反鐵律 5）。
3. 手刻的風險原本是「沒有動畫」，但 Slater CSS 是用 **class selector**（`.glass-button:hover .gradient-icon.is-1`）
   驅動箭頭，不需要 `data-w-id`，沿用同一組 class 就會有同一個動畫。
   文字逐字動畫是 Slater JS 讀 `data-button-animate-chars`，這顆按鈕沒有文字，用不到。

### 無障礙與捲動

- 圖示型連結沒有可讀文字，因此 `<a>` 上掛 `aria-label="ページトップへ戻る"`。兩顆 SVG 都是 `aria-hidden="true"`。
- 捲動用 Webflow 原生 anchor：`link = "#page-top"`（`linkType: url`，避開 `06` §1 的 `linkType: page` 靜默失敗），
  目標是最上層 hero section `534fcc9e-…-f26f` 新掛的 DOM id `page-top`。沒有寫任何 JS。
- **不是**捲動才浮現的 floating toggle。scroll-triggered 顯示／隱藏要靠 IX2，而 MCP 讀不到也寫不了 IX2
  （`06` §8）。codex 那版是用 page custom code 的 JS 達成浮動效果，這條路被 Terris 否決。
  若之後確定要浮動版，正解是在 Designer 手動加 IX2（Scroll into view／Page scrolled），不是再寫一段 JS。
