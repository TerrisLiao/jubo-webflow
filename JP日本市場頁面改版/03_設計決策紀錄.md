# 03 設計決策紀錄

> 這份記錄**為什麼**這樣做。想知道「現在長什麼樣」看 `02_頁面現況規格.md`。

## 1. 為什麼 about-us 要獨立存在，不併進 overview

日本 B2B 客戶「查公司信用」與「看產品說明」是兩種閱讀情境。
39 家日本官網樣本收斂出的共識裡有一條很明確：
**会社概要必須能由明確入口找到，不能只藏在 footer** —— 把公司資料併進又長又產品導向的 overview，
等於重蹈那個失敗模式。

其他從樣本得到的共識（構成 about-us 的設計基準）：

- 最小可信資訊：法定公司名、代表人、成立日、據點地址、事業內容。
- 資本額、員工數、投資人、認證等，**只在可維護且可查證時才加**。
- 公司概要通常用 **label/value 表格**，不是多張行銷卡。
- Access（據點）常緊接在会社概要之後，或獨立呈現。

> 已研究樣本共 **39 家**（不是 50 家）。Terris 決議**跳過**補到 50 家 —— 共識已經很清楚，邊際效益不足。

## 2. 為什麼改成條列／表格，不用卡片

Terris 的判斷：這頁「本身有點空」，而且「用卡片做很難讀」。

診斷：空的原因**不是頁面不該存在**，而是它把**可查證的事實寫成了行銷散文再裝進卡片**。
指定參考站 BETA（`b-inc.co.jp/about-us`）那頁之所以不空，是因為它的会社概要是**一張很長的 label/value 表**，
塞滿主要株主、取引銀行、認証、主な取引先等可查證項目。

**原則：該掃讀的資料就讓人掃讀，該讀故事的地方才用散文。**

## 3. 受眾定位如何影響版面

Terris：「這個設計方式是主要給**代理商**⋯⋯想要購買產品就叫他導過去 MDX。」

因此 about-us **刻意不追求設計感**：沒有 Hero、沒有敘事段落、沒有品牌宣言。
創辦人、Manifesto、歷程、多職能團隊等敘事段落**全部移到（或保留在）overview**，
about-us 只留可查證的公司資料 + 據點 + 詢問窗口。

## 4. 經營團隊卡片：為什麼是玻璃疊層 + 2×2 階梯

視覺語彙沿用 `/internship` 既有的 `intern-voice_card`（照片滿版 + 底部半透明玻璃面板疊字），
而不是站上另一組 `glass-effect__*` 多層堆疊 —— 後者是**按鈕專用**的高光/陰影堆疊，不適合人像卡。

過程中收斂出的幾個關鍵判斷：

- **玻璃面板必須固定高度**：面板原本高度隨簡介字數自動長，導致四張卡面板頂端高低不齊。
  改成外層疊層固定 `height: 40%`、內層玻璃面板 `height: 100%` 撐滿，四張卡才會完全等高頂齊
  （簡介短的卡在面板內留白，是刻意的）。
- **卡片比例 = 照片原始比例（2:3）**：`object-fit: cover` 在容器比例等於圖片比例時**裁切量為零**，
  這是「不留白邊、又最不放大人物」的技術極限。中途曾試過 3:4、3:5，都會產生裁切＝局部放大。
- **白色留白外框試做後否決**：Terris 要求試「白邊會不會增加設計感」，做完後決定不要，改回滿版。
- **間距的責任要放在網格、不是卡片**：曾用「卡片自己 `width:60%` + `margin:auto` 置中」來縮小卡片，
  結果每張卡兩側各留 20% 空白、疊加 grid gap，左右間距看起來誇張地遠。
  正解是**讓卡片填滿格子，改為整個網格區塊縮小置中**，間距才由 gap 單獨決定。

### 照片裁切為什麼需要 `is-cro` / `is-cto` 兩個變體

四張原始照片同尺寸（2:3），但每個人在畫面裡的構圖不同。用程式量測髮際線像素位置
（背景灰階 vs 頭髮灰階差值 > 40 判定）：

| 人物 | 髮際線位置（佔圖高比例） |
|---|---|
| CEO 康仕仲 | 14% |
| CDO 李泓其 | 15% |
| CTO 古凱元 | 20% |
| CRO 謝美芬 | 21% |

用同一個裁切錨點，CEO／CDO 的頭會被切到；統一往上偏（`50% 20%`）之後 CEO／CDO 對了，
但 CRO／CTO 因為頭頂留白較多，看起來比另外兩人矮一截。
因此**只針對這兩張**建 `is-cro`（`50% 40%`）與 `is-cto`（`50% 37%`），讓四人髮際線落在同一相對高度。

> ⚠️ 這是「combo 只為了裁切位置微調」的少見用法。**日後加新成員要先量髮際線再決定**，
> 不要直接套 base class 就假設一致。

## 5. 導覽與 logo：為什麼不做獨立 header

曾經自建一條固定在頂部的 header bar 放「企業情報」按鈕，**方向是錯的**，原因有二：

1. 站上既有語彙是 **logo 直接疊在 hero 圖上**（overview hero 本來就有一個白色 Jubo 字標在左上角）
   —— 另做一條 bar 與之衝突，也會把內容往下推。
2. 我在自建的 header 裡又放了第二個 logo，等於同一頁出現兩個 logo。

**正解**：把按鈕做成 hero 的絕對定位子元素，放在**右上角、與既有左上角字標對稱**，
定位數值完全鏡像既有 logo 的 `is-top-left` combo（含三個斷點偏移）。
視覺上有導覽列的感覺，但不需要真的多一條 bar。

> **教訓**：要加「導覽／logo」這類全站級元素前，**先把該頁 hero／header 的既有結構讀完**。
> 這次如果先查了 hero，就會直接看到 logo 已經存在，不會白做兩輪。

### 按鈕本體必須用 Glass Button component，不能手刻

手刻的靜態按鈕看起來像，但**完全沒有動畫**。
站上按鈕的文字逐字位移由 Slater 驅動、箭頭滑入滑出由 Webflow Interactions（IX2）驅動，
兩者都不在 CSS 裡、MCP 也寫不了。詳見 `06_Webflow實作陷阱.md` 第 8 條。

### about-us 的 logo 為什麼改用 inline SVG

Terris 上傳的 logo PNG **含大量透明留白**：畫布 2196×1049，實際有顏色的內容只有 1559×407，
**只佔畫布高度的 38.8%**，且內容從畫布頂端 30.6% 處才開始。造成兩個問題：

1. 設 `height: 2.25rem` 時，可見字標其實只有約 14px —— 看起來小得不合理。
2. 要讓**可見字標**對齊 `top: 2rem`，外框得設成負的 top，但 `.all-sections-wrapper` 是 `overflow: clip`，負偏移會被裁掉。

**正解**：改用與 overview hero 相同的 **inline SVG**（緊貼字標、零留白），只是顏色改成品牌藍 `#00B2C0`。
尺寸完全可預測（`height` 就等於可見高度），也不依賴圖片上傳的非同步處理。

> 另一個關鍵查證：about-us 的 `container-large` 的 `max-width` **正好也是 `82rem`**，
> 與 overview 那條 `calc((100vw - 82rem) / 2)` 公式用的值相同，
> 所以兩頁 logo 能對齊到**完全相同的左邊界**。

## 6. 表單為什麼用顯性標籤而不是 placeholder

原本模仿 `/contact` 改成「無標籤、只靠 placeholder」，結果**欄位全空**——
因為 **MCP 無法設定表單 placeholder**（`/contact` 的 placeholder 是在 Designer UI 設的）。

改回顯性標籤，但**不能用 `jp-about_profile-label`**（那是公司資訊表格的窄欄標籤 class，
只夠放 2–4 個字，長標籤會逐字換行變成三行堆疊）。
新建 `jp-about_field-label`（`white-space: nowrap`）放在輸入框上方。
