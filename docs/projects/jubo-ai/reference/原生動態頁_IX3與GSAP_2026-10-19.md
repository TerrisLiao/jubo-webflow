## 2. 為什麼改成這個架構

v7–v11 都是 iframe 裡的單一 HTML，動畫各自為政，Designer 無法編輯。這版改為：

1. **內容是 Webflow 原生元素**：11 個 section、Client-First class（前綴 `jubo-ai-film_`），Designer 可直接改字、改位置。
2. **鏡頭感來自一個導演**：所有場景的玻璃鰭片與光，都由頁面上的錨點元素（`[data-fin="0..7"]`、`[data-light]`）定義位置。WebGL 只有一張固定全螢幕 canvas，依「哪幾個場景在畫面上、各占多少」混合錨點矩形並阻尼追隨，所以鰭片在場景之間連續變形，像同一顆鏡頭一路拍下去，而不是每段各自淡入淡出。Designer 移動錨點，光與玻璃就跟著移動。
3. **分工**：IX3 負責 Designer 看得到的進場（首屏、標題逐行、柔和浮現）；GSAP 負責 pin、scrub、模糊、畫線、計數、打字、遮罩擦除、對話與彈窗。兩者目標元素不重疊。

## 5. 技術要點

- WebGL1、無 Three.js；單一 fragment shader：四團漂移光（依場景 `data-light-hue` 換色：青、天空／薄荷、沙／萊姆、薄荷／天空）＋游標光團；每片鰭片內做長虹折射（反向取樣＋凹槽偏移）、磨砂、飽和、棱線高光、掃光與側邊亮線，上下淡出所以沒有面板邊緣。canvas 以 `clip-path` 只顯示在根元素可見範圍。
- 效能：DPR 桌機 ≤1.5、手機 ≤1.25；IntersectionObserver 與分頁隱藏時停止迴圈；「暫停動態」按鈕；手機光強 ×0.72。
- 無 WebGL：根元素 `data-gl="off"`，錨點改用 CSS 磨砂鰭片＋模糊光暈 div。
- 診斷：`window.juboAIFilm`（mode、gl、draws、pins、`fins()`、`light()`、`weights()`、`goTo(name, p)`），不含個案或使用者資料。

## 8. 2026-10-28：主視覺由長虹玻璃改為光之花瓣

Terris：「now the actual page is way better in webflow. but i dont like the glass design」，附四張參考：Bloom（半透明層疊花瓣＋下方輸入列）、紫色漸層光團＋玻璃節點 pill、AI Popup（粉彩漸層卡）、Verba AI（白卡內柔和彩虹光＋輸入列）。

**決定**

- 取參考的**形體語言**：乳白、半透明、層疊的有機花瓣，柔和的邊緣光，暖色根部；白色圓角卡內帶粉彩光暈。
- **配色維持無紫色**：色調用 Jubo 青、天空、薄荷、蜜桃。這是延續 Terris 2026-10-19「紫色太多、很醜」的裁決。若要參考圖的薰衣草色，只需改 shader 的色票。
- 不使用參考圖 2、3 的大圓球與虛線圓（延續「不要圓形與泡泡」）。

**做法**

- **WebGL**：每個 `[data-fin]` 錨點不再畫長虹折射，改畫一片花瓣。花瓣形狀是 uneven capsule 加上彎曲、不對稱與邊緣起伏，從共同根部長到錨點頂端。
  - 根部位於可見錨點群的中心下方，所以多個錨點會開成一束花；單一錨點時，花瓣直接從錨點底部長出。
  - 水平錨點（caps 掃描列）畫成橫躺的葉形。
  - 花瓣中心依序取青、天空、薄荷，部分帶蜜桃色；根部為暖色；邊緣是柔和的白色光暈，外圍有暈光；掃光速度隨「思考」加快。
  - 背景光降到 0.4 倍，讓顏色主要落在花瓣上。
- **首屏**：5 個錨點收攏成直立花束（桌機 31–69%，767 以下 22–78%），思考列移到花的根部（79%），做成 Bloom 的輸入列樣式（白色 pill、暖色陰影）。IX3 的 scaleY 進場因此變成花瓣從根部長出。
- **介面**：
  - 對話框與資料卡改為白色大圓角卡，內部有緩慢漂移的粉彩光暈（Verba 樣式）。
  - 提示按鈕改為淺灰 pill。
  - 資安遮蔽條由長虹條紋改為柔光帶。
  - 無 WebGL 時，fallback 改為 CSS 花瓣。
- **文案**：首屏提示改為「移動游標，花瓣裡的光會跟著你思考」；觸控版提示改為「輕觸畫面，花瓣裡的光會回應你」。

## 9. 2026-10-28：主視覺改為長虹玻璃後的 S 形光帶

同日稍晚，Terris 附兩張參考：細密的垂直長虹玻璃後方，一條粉、藍、青（或藍、紫）的 S 形柔光帶，被折射成階梯狀，沒有面板邊框，四周淡入白底。原話：「主視覺的動畫要修改，需要像是這種」。§8 的花瓣因此由這個做法取代；白卡、提示按鈕、柔光帶等介面調整保留。

**做法**

- **WebGL**：玻璃範圍取可見 `[data-fin]` 錨點的外框，向外留邊並限制在視窗內，經阻尼追隨，所以在場景之間仍會連續變形。範圍內畫一條 S 形光帶：
  - 以 tanh 做 S 形，再加上兩層正弦起伏。
  - 寬度會呼吸。
  - 顏色由上而下為粉、藍、青，沿光帶方向緩慢漂移。
  - 每條凹槽（寬為範圍寬度的 1/26，限制在 12～30 px）只取光帶的一窄條，並依凹槽內位置做垂直位移，因此光帶邊緣呈階梯狀，與參考相同。
  - 凹槽邊緣只有極淡的明暗，四周淡入紙色，看不到面板。
- **動態**：
  - 光帶持續起伏，S 的方向約每 45 秒緩慢翻轉一次，在兩張參考的形狀之間轉換。
  - 游標會把光帶拉向自己；點擊時沿光帶送出波動。
  - N.Copilot「思考中」時光帶變粗、動得更快。
- **首屏**：錨點改為 18%～82% 的較寬分布（767 以下維持 22%～78%）。思考列仍在下方 79%。
- **fallback**：無 WebGL 時改為 CSS 細條紋疊在粉藍青漸層上。
- **文案**：提示改回「移動游標，玻璃後的光會跟著你思考」。
- **配色**：依這兩張參考，主視覺光帶帶有粉與淡紫；版面其他部分仍以 Jubo 青為唯一強調色。這是依新參考做的調整，若要回到無紫色，只需改 shader 中三個色票。

**技術註記**：WebGL1 的 GLSL 沒有 `tanh`，改用自寫的 `tanh1()`。編譯失敗時 shader 會靜默退回 fallback，驗收腳本以桌機 `gl === "on"` 檢查擋下。
