## 2. 策略與資訊完整性

受眾為機構經營者、護理／居服主管及合作夥伴；主目標為與 Jubo 討論應用需求。核心仍是 Knowledge + Data + Workflows → Jubo AI → Capabilities → Applications。

用捲動先回答「懂哪些知識、有哪些資料」，再揭露「可以怎麼用、已有哪些應用、誰做判斷」。CTA 維持 Talk to Jubo → /contact；信任來源是原版資料分類、已有應用、原品牌素材與 Security 入口。

| 段落 | 呈現 |
|---|---|
| Hero | 置中主張、獨立互動球體、Scroll to discover |
| Opening | Care knowledge → Everyday experience → Deeper understanding 逐行顯現；知識範圍與 30 億筆平台紀錄 |
| Foundation | 五類資料逐幕揭露，每幕一個置中標題、資料細項與對應用途 |
| Understanding | 同一球體獨立出現，從紀錄到理解；沒有環繞卡片 |
| Capabilities | 五種能力逐幕顯現；一次一張中央玻璃示意，保留各自動畫 |
| Applications | N.Copilot → Amy → iBee，逐幕置中展示，沒有產品卡片網格 |
| Possibilities | 三個 What if 提問逐幕揭露，可開啟構想說明 |
| People／CTA | AI supports. People decide. → 合作 CTA |

五類資料與細項延續 v4 完整清單：Care records、Vital signs、Handover notes、Home visit records、Family updates。能力為 Find、Summarize、Notice changes、Draft、Discover insights。

N.Copilot 為專案型對話應用；Amy 為系統內脈絡整合；iBee 為跨平台流程自動化。不將 Amy／iBee 塞進 Copilot 的對話工具選單，不把 iBee 寫成資料庫訓練產物。所有對話均明示示意、沒有真實個案或 live action。未來構想不宣稱已上線。

## 3. 捲動與置中

- 桌機／足夠高度：sticky 全螢幕舞台，僅當前幕可操作、可被輔助科技讀取；其他幕 inert／aria-hidden。
- Foundation、Capabilities、Possibilities 每幕約 105svh 的捲動距離，Applications 約 120svh。中段停留，前後漸入／漸出。
- 捲動位置平滑追蹤；沒有阻擋 wheel、沒有強制接管原生捲動。
- 每段有章節按鈕可直接前往任一幕，避免必須完整重走長頁。
- 手機、矮視窗、reduced-motion 改自然文件流，依序置中顯示全部內容，不使用 pin。
- Hero 與 Understanding 的球體容器皆為空的獨立 slot，不放入資料卡、玻璃框或環繞節點。

## 4. 球體與品牌材質

單一 Three.js r155 shader plane、單 canvas、單 draw call，沒有粒子或新增 3D 物件。球體互動包含：

- 滑鼠接近球體時，球面有低幅牽引與形變。
- 左右／上下移動改變球面取樣方向、高光與內部色帶。
- 離開後平滑回到中性；觸控球體有短暫脈動。
- 保留 v4 的柔亮邊緣、半透明色帶、光場；背景加入窄幅折射語彙。
- Pause／Resume、分頁隱藏停止、reduced-motion、WebGL 不可用的 CSS fallback。
