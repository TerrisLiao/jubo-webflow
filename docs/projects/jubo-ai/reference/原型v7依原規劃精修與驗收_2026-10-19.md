Terris 認為現行 Draft（v6）很不好看，要求依 git 脈絡回到「原先的規劃」精修一版。

讀回 v1–v6 的 decisions、交接與驗收紀錄後，判定 Terris 已確認、但 v6 偏離的規劃為：

| 原規劃（來源） | v6 實際 | v7 |
|---|---|---|
| 白底**漸進顯色**、平滑 glowing orb、磨砂玻璃＋長虹玻璃（v4 架構「ok」） | 移除全頁漸層與長虹，只剩灰白與單色球 | 白底隨章節慢慢加入青／藍／紫光場，Understanding 章到達高峰並出現長虹折射，結尾淡回白 |
| 置中、沉浸式、隨捲動慢慢揭露（v3、v5 裁決） | 保留，但 16 幕各只有一行標題＋三個字，整頁約 26 個視窗高 | 保留置中與逐幕揭露；改成 7 章、每幕都有完整示意，整頁約 18 個視窗高 |
| 球體獨立、與滑鼠互動、融入 Jubo 品牌色與 CTA（v5 裁決） | 保留 | 保留；球體加入 CTA 漸層的藍紫色帶、外光暈，Hero 放大 |
| 全英文；資料 → 能力 → 應用；N.Copilot＝對話應用、Amy／iBee＝系統 add-ons；What if 明示可能性（v4） | 保留 | 全部保留，文案與五類資料、五種能力、三個應用、三個構想一致 |
| 官網字體與字級 | 改系統 Helvetica／Arial，內文約 11–13px、低對比灰 | 回到官網 Poppins，桌機內文 18px（同官網 body）、手機 16px，標題 400 字重 |

v6 的質感問題主要是執行層：字太小、灰字對比不足、每幕內容過少而留白過多、轉場停在半透明（捲動綁定透明度）。

## 2. 章節

| 章 | 內容 | 互動／視覺 |
|---|---|---|
| Hero | AI that understands care.、主次 CTA、互動球體 | 球體跟隨游標；光場淡青 |
| Statement | Care knowledge. / Everyday experience. / Deeper understanding.；照護領域；3 billion records、2,800+ organizations | 逐字隨捲動由淡轉深 |
| Foundation | 五類資料逐幕：Care records／Vital signs／Handover notes／Home visit records／Family updates | 每類一張玻璃紀錄示意＋「Helps teams」能力標籤；上方分頁可直接跳幕 |
| Understanding | From records to understanding.、球體、三行說明 | 光場高峰＋長虹折射；三行依序出現 |
| Capabilities | Find／Summarize／Notice changes／Draft／Discover insights | 每項一個玻璃視窗動畫（搜尋、彙整、趨勢、草稿、長條） |
| Applications | N.Copilot（三個示意對話、來源、review）、Amy、iBee | 第一次抵達自動播放一段示意對話；Amy 匯整、iBee 讀取→比對→匯入 |
| Possibilities | 三個 What if 大字提問＋構想彈窗 | 逐字顯現；明示「not current products」 |
| People／CTA | AI supports. People decide.、三原則、Security 連結、結尾球體與 CTA | 光場淡回白底 |

桌機（寬 ≥768、高 ≥680）用 sticky 舞台，每章固定一個標題與分頁，內容依捲動**離散切換**（淡出→延遲淡入，無半透明殘影）。手機、矮視窗與 reduced-motion 改自然文件流，所有內容依序完整顯示。

- 現行 Jubo Glass Button 七層結構沿用 v5／v6 讀回版本；N.Copilot wordmark／mark 兩條原稿 path 未改。
- 所有示意標明 Illustration／no real data；N.Copilot 對話標明沒有真實個案或系統動作。
- 未修改 Webflow 共用 Component、Variables、utility、Slater 或站台腳本；Poppins 為官網既有字體，未新增品牌 Variable。
- v2–v6 HTML 保留未改。
