# 02 逐篇盤點表

**本專案的核心產出。** 87 篇每篇一列，每列都要有 Terris 確認過的決策 —— 結案時不能有空白列。

現在是骨架。實際 87 列由本機 session 的批次盤點填入。

## 盤點方法：批次 subagent

單篇 Rich Text 平均約 40KB、87 篇約 3.5MB，**不可能在單一 context 讀完**（2026-09-03 實測：一次抓 2 篇即 80KB 超出單次工具輸出上限）。而 `12_AEO文章寫作指南.md` 規定改寫只能走 **CMS API 寫整段 HTML**。

所以採「每個 subagent 吃 4–6 篇、各寫自己的批次檔、最後合併」：

1. 用 `data_sitemap_tool > list_items_sitemap_status`（collection `69f82ba2b2602e6d6594d689`，limit 100）列出全部 87 筆。這個 API **只回 id / slug / name / includeInSitemap，不含 Rich Text**，是唯一輕量的列舉方式。
2. 切成約 18 批，每批 4–6 篇。
3. 每個 subagent 用 `data_cms_tool > list_collection_items` 讀回自己那批，填表寫進 `batches/批次NN.md`。**只讀回填表，不改任何 Webflow 內容。**
4. 各寫各的檔避免寫入衝突。全部完成後合併進本檔。
5. 批次檔保留供追溯，不刪。

### 怎麼分辨 WordPress 遷移批次

item id 前綴 `6a1121*` 或 `6a1122*`，且 `createdOn` 為 `2026-05-23`。這 72 篇就是遷移匯入的舊文章，本專案的主要標的。其餘 15 篇是 Webflow 上線後原生產出。

## 欄位定義

### 定位

| 欄位 | 說明 |
|---|---|
| `#` | 序號 |
| `slug` | URL slug |
| `標題` | `name` 欄位 |
| `item_id` | CMS 操作用 |
| `來源` | `WP遷移`（id 前綴 `6a1121*`/`6a1122*`）｜`Webflow原生` |
| `publish-date` | 空白要標出來 |
| `分類` | 7 個新聞類別之一，或未分類 |
| `字數` | Rich Text 轉純文字後的字數 |

### 授權

| 欄位 | 說明 |
|---|---|
| `授權燈號` | 🔴 / 🟡 / 🟢，判定標準見 `04_著作權處理紀錄.md` |
| `授權理由` | 一句話。例如「全文轉載世新新聞，未見授權標示」 |

### 結構（對 `12_AEO文章寫作指南.md`）

| 欄位 | 合規值 |
|---|---|
| `H1 數` | **應為 0** —— 模板已提供 H1，內容自帶 H1 是缺陷 |
| `H 層級是否跳級` | 否（H1→H2→H3，不可 H1 直接接 H3） |
| `H2 數` | > 3 就該加目錄 |
| `問句標題比例` | H2/H3 中寫成問句的比例（知識型文章才適用，公告不適用） |
| `img 數 / 缺 alt 數` | 缺 alt 應為 0；且 alt 要是**資訊型**（含活動時間／講者／圖表數字），不是「示意圖」 |
| `外部圖床` | 有沒有非 `cdn.prod.website-files.com` 的圖片 src |
| `外部連結網域` | 出站連結去哪些網域 |
| `short-summary` | 有 / 空白（空白直接影響搜尋與 AI 摘要品質） |
| `cover-image + alt` | 有 / 無 / alt 空白（`11_` 記載新聞內頁 H1 下方主視覺就是 `alt=""`，而那張圖含活動時間、主題、主講人） |
| `有目錄` | 是否已有 `.aeo-toc` |
| `有 FAQ` | 是否已有 `.aeo-faq` |
| `WP 殘留` | `wp-content`、`wp-image`、`wordpress`、`elementor`、inline style、`&nbsp;` |

### 排序（CrawlSEO / GSC）

| 欄位 | 說明 |
|---|---|
| `clicks` | GSC，過去 16 個月 |
| `impressions` | GSC |
| `position` | GSC 平均排名 |
| `主查詢` | 帶來最多曝光的查詢 |
| `decay 訊號` | CrawlSEO content decay 報表 |
| `cannibalization 對手 URL` | CrawlSEO cannibalization 報表 —— **這一欄就是 301 併入 pillar 的依據** |

⚠️ **拿不到排序資料的篇目，這幾欄留空並在 `決策` 欄標示「驗證限制：無 GSC 資料」，不得直接判定下架。**（`CLAUDE.md`：snapshot 過期或無法取得時必須標示驗證限制，不得宣稱完成）

### 決策

| 欄位 | 說明 |
|---|---|
| `主題群組` | 要併進哪支 pillar（見 `06_`），或「不併」 |
| `分流` | T1 保留原樣 / T2 併入 pillar / T3 保留輕修 / T4 下架 / T5 結構歸位 |
| `決策` | **Terris 逐列確認欄，初始空白** |
