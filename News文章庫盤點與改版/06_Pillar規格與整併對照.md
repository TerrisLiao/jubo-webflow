# 06 Pillar 規格與整併對照

## 為什麼是 pillar 整併，不是逐篇改寫

內容策略已轉向品質優先、不量產（見 `01_`）。72 篇 WordPress 舊文如果逐篇改寫，結果是 72 篇平庸內容互搶關鍵字 —— 那正好是 Notion 點名要避免的「為 AI 量產內容」。

正確做法：**把舊文當素材與 301 權重來源**，依 GSC 訊號立少數幾支支柱頁，同主題舊文全部 301 併進去。權重集中、篇數變少、品質拉高。

CrawlSEO 的 **cannibalization 報表就是整併依據** —— 它會直接指出哪些舊文在互搶同一組關鍵字，那份名單就是要併進同一支 pillar 的名單。

## 寫作規格

**規範本身讀 `Jubo官網AI開發規範/12_AEO文章寫作指南.md`，這裡只寫怎麼套用在 pillar 上。**

### 建立方式

- **pillar 是新建 CMS item（新 slug）**，舊文以站台層級 301 導入
- **不要把某篇舊文改寫成 pillar 再改 slug** —— 改 slug 會斷掉所有引用舊 slug 的連結
- 一次寫進 Draft，填齊 `Content`、`Short Summary`、`Name`、`Slug`、`Publish Date`、`News Categories`、`Cover Image`
- 專屬 FAQ 問答放 `Schema Plain Text` 欄位（本來就是為此設計，不需要新欄位）

### 結構（來自 `12_`）

- **內容內 H1 數為 0** —— 模板已提供 H1
- H 層級連續：H2→H3，不跳級
- 段落開頭先給答案，細節往下鋪陳
- H2/H3 寫成使用者真的會問的問句，不是形容詞式標題
- 比較內容用**表格**，不用散文
- **H2 超過 3 個就加目錄**（`custom-code/poc/news-toc-tagcloud.html`，只換內容與 `data-heading`／heading `id`，不重新發明外觀；**不可掛 `.glass-button`**，那是 Slater 綁定）
- FAQ 放結尾或段落之間，自然放，不硬湊（`custom-code/poc/news-faq-accordion.html`）
- 每張圖有**資訊型** alt：含活動時間、講者、圖表數字，不是「示意圖」
- `Short Summary` 一定要填 —— 這是 SEO description 來源

### 表格

只能走 CMS API 寫整段 HTML（inline style）。顏色只用四個 Variable：`--neutral--white`（卡片底）、`--neutral--bg-grey`（表頭底）、`--neutral--black`（文字）、`--neutral--black-60`（內部分隔線）。**不手打色碼。** radius 固定 `2rem`、外框 `border:0`、最後一列不留 `border-bottom`、保留外層 `overflow-x:auto` + table `min-width`。

⚠️ `12_` 的**分組變化樣板（含 zebra stripes）尚未做過視覺驗證**。第一次用在正式文章前，一定要先進 Draft 用 snapshot 或 Editor 預覽，桌機／手機都看過。

### 策略原則（Notion）

- 每篇一個主關鍵字，其他詞只作自然延伸，**不把多個同義詞堆進標題**
- 開頭先直接回答問題，再給流程／比較表／checklist，**最後才承接 Jubo 方案**
- 分眾：住宿型 / 日照 / 居服**不要寫成同一篇通用文章**
