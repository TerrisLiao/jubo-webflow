# 03 下架與 301 對照表

T4（下架）與 T2（併入 pillar）的舊 URL 導向紀錄。**每條都要有實測結果 —— 不是「已設定」而是「已驗證」。**

## ⚠️ 先解決 P0-1：CMS 的「301 Redirect」欄位可能產生不了真正的 301

Collection 上有 `301 Redirect`（slug `301-redirect-2`，Link 型別），**但 CMS item 上的欄位不會產生 HTTP 301** —— 它只能被新聞模板讀出來、靠前台 JS 做 client-side 轉址。

如果是這樣，**item 一 unpublish，那個轉址就跟著消失，URL 直接變 404**，整個「Unpublish + 301」策略會失效。

開工前必做：

1. 查新聞模板頁與 Slater `60292.js` 有沒有讀這個欄位。起點：`custom-code/slater-selectors.md`。
2. 抓一篇已填該欄位的**線上 HTML 實測跳轉行為**。不能只信 API 回報。
3. 真正的 301 幾乎確定要下在 **Webflow Site settings → Publishing → 301 Redirects**（站台層級）。
4. 確認目前 Webflow 方案的 redirect 剩餘條數 —— **pillar 整併會用掉 30–40 條**。

**條數不夠的備案**：改成「保留頁面 + 移出 sitemap」，不 unpublish。
