## 3. 導覽列：不是「換成 IX3」這麼簡單

### 3.1 主導覽列（mega menu）根本不是 IX2

桌機 mega menu、手機抽屜、手機選單內的手風琴，**全部由 Slater JS 驅動**
（`60292.js` 第 1924 行起的 `Mobile Drawer` 區塊，以及 mega menu 區塊）。

9/22 盤點裡寫的「Navbar/Dropdown 6 個 API 做不到」，實際上：

| IX2 事件 | 真相 |
|---|---|
| NAVBAR_OPEN/CLOSE（Navbar 3） | 只在 `/ecosystem/jubo-digital`，是該頁殘留的模板導覽列 |
| DROPDOWN_OPEN/CLOSE ×4 | **孤兒** —— 元素不存在於任何已發布頁面 |

**所以「API 不支援 navbar trigger」這個硬限制，對主導覽列不適用。**

### 3.2 🔴 手機漢堡選單有三套程式在搶同一個抽屜

漢堡按鈕 `.mobile-menu-icon_wrap`（128 頁）上，實測綁了：

| 驅動者 | 做什麼 |
|---|---|
| **Slater JS** | 抽屜 `display`／`opacity`／`transform`、鎖背景捲動、停 Lenis、分隔線動畫、收合手風琴 |
| **IX2 `e-337` → a-70** | 抽屜 `display:flex`、`x:0`、`opacity:1`；漢堡兩條線旋轉成 X |
| **IX2 `e-339` → a-70** | **完全一樣的東西，又綁了一次** |
| （關閉同理：`e-338`、`e-340` → a-71） | |

也就是每按一次漢堡，**抽屜的同一組屬性被三個來源同時寫入**
（Slater 450ms ease、IX2 200ms ×2）。目前看起來沒壞，是因為終點值剛好一致；
但這正是「改一邊、另一邊默默打架」的標準地雷。

**唯一只有 IX2 在做的事**：漢堡兩條線（`.menu-top-lline.is-white`／
`.menu-bottom-line.is-white`）轉成 X。

### 3.3 導覽列的正確改法

1. 抽屜本體**交給 Slater 就好**（它本來就做得最完整：鎖捲動、Lenis、手風琴），
   IX2 對抽屜的動作全部移除。
2. 漢堡 → X 的線條動畫用 IX3 重做。頁面上只有一個漢堡，
   `wf:class` 選到的就是唯一那一個，**CHILDREN 限制在這裡不成立**。
3. 風險：Slater 若從其他路徑關閉抽屜（點連結等），IX3 的 toggle 狀態會反。
   動工前要先確認 Slater 的所有關閉路徑，並逐一實測。
4. 導覽列是**共用元件**。依 CLAUDE.md「不直接修改共用 Component」，
   動工前需要 Terris 明確同意。

## 4. 修正後的遷移地圖

**IX3 的 CHILDREN 限制只卡「重複出現的元素」。** 單例元素（每頁只有一個）
用 `wf:class` 選到的就是那一個，可以忠實重現。

| 類型 | 項目 | 觸發數 | IX3 可行性 |
|---|---|---|---|
| 單例 | Cookie／Preferences、漢堡線條、Modal ×3、Header 系列、timeline | ~44 | ✅ 可忠實重現 |
| 重複元素 | Glass Btn、Stats Color、FAQ、Img Hover、CTA Loop、Product Item | ~101 | ⚠️ 必須依 `21_Jubo動效準則` 重新設計 |
| 孤兒 | — | 235 | 🗑 只需刪除 |

### ⚠️ 刪除這件事 API 做不到

MCP 只能建立／修改／刪除 **IX3**，**讀不到也刪不掉 IX2**。
所以不論是 235 個孤兒、還是遷移完成後的舊 IX2，**都要有人在 Designer 裡手動刪**。

建議做法：我產出一份「要刪的 IX2 清單」（互動名稱＋所在頁面＋元素），
Terris 照清單在 Designer 的 Interactions 面板逐一刪除，刪完我再重新解析驗證。

  半成品會一起上線。要改正式站上的文字或 CMS，請先告知。

### 孤兒：不刪

| | 大小 |
