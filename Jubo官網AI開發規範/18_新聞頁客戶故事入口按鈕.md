## 3. Class（folder `news-story-link`）與 IX3

沒有修改任何既有 class、component 或變數。

| Class | 重點 |
|---|---|
| `_component` | flex、置中、`width:auto`（寬度跟著內容）＋`max-width:100%`、`gap:2rem`；small `width:100%`、圓角 `1.5rem`（small `1.25rem`）、內距 `1.25rem/1.25rem/1.25rem/1.5rem`、`white-50` 玻璃底＋白邊＋`backdrop-filter: blur(12px)`、柔和陰影；`position:relative; overflow:hidden; isolation:isolate`（給光澤層用）。small：換行（頭像一行 → 文字一行 → 按鈕一行）。CSS 只做陰影 transition，位移交給 IX3 |
| `_avatars` / `_avatar` | `3rem` 圓形、白色 2px 邊、`margin-left:-0.875rem` 疊排（容器 `padding-left` 補回）；tiny `2.5rem` |
| `_content` / `_eyebrow` / `_title` | eyebrow 為品牌漸層文字（`background-clip:text`）；title `1.125rem`（tiny `1rem`）；`_content` 桌機 `flex:0 1 auto`（不撐開），small 以下 `flex-basis:100%` 自成一行 |
| `_cta` / `_cta-arrow` | 品牌漸層 pill、白字、紫色柔光、內距 `0.875rem 1.5rem`；**各斷點都維持內容寬度，不拉滿** |
| `_aura` | 卡片內第一個子元素，`position:absolute`（上下 -60%、左右 -15%，留出漂移空間）、`z-index:-1`（靠 `_component` 的 `isolation:isolate` 留在卡片內、內容之下）。背景為四個 radial-gradient 疊成的網格漸層：teal `#00b2c0` 30%、紫 `#b15dff` 24%、淺 teal `#9df8ff` 55%、藍 `#3b58ff` 16%（色值同 Jubo Variables，因需要不同透明度而手寫 rgba）。取代原本 `_component` 上的靜態 `background-image` |
| `_glow` | 與 `_aura` 同層（`z-index:-1`，DOM 在 `_aura` 之後所以疊在上面），上下 -50%、左右 -10%，**平常 `opacity:0`**。網格漸層濃度明顯高於 `_aura`：teal 65%、紫 55%、淺 teal 90%、藍 30%。只在 hover 時由 IX3 淡入並放大 |

## 4. 歷程：前兩版為什麼不採用

第一版（同日）把按鈕做成 `a.cta-button.is-customer-story`，**放在 `news-filter_form` 篩選列裡面**、排在類別按鈕最後。
Terris 回報截圖：**篩選按鈕全部被擠到文字換行、嚴重變形**（「所有文 / 章」這種斷行）。

原因：`news-filter_form` 是不換行的 flex row，原本的篩選按鈕剛好放得下；多塞一顆按鈕後總寬超出 container，
其他按鈕被 flex 壓縮，而篩選按鈕的文字沒有 `nowrap`，就被擠成兩行。

另外 Terris 指出設計方向也不對：篩選按鈕是「篩選這頁」，客戶故事是「前往另一頁」，兩者應該在視覺上明確區分、而且入口要放在所有按鈕上方。

已處理：刪除第一版元素與 `cta-button > is-customer-story` combo（Style Manager 無殘留），改為本文件的第二版。

第二版（同日）：移到篩選列上方，做成「漸層小標籤＋說明＋白色圓形箭頭」的玻璃 pill。不再跑版，但 Terris 評為「設計品質不好」——元素平均、像模板、沒有動態。第三版改為真實頭像＋清楚的 CTA 層級＋IX3 動效，並刪除第二版的 `_tag`／`_text`／`_icon` 三個 class。

**教訓：不要往既有的 flex row 裡塞東西，除非先確認它在最寬的內容下還放得下。**
另外，Slater 會對 `.news-filter_form` 內每個 `.cta-button.is-filter` 切換 `is-active`，手機版還會藏掉 form 直屬的 `.cta-button.is-filter`；
這也是另一個不該把非篩選元素放進這個 form 的理由（見 `custom-code/slater-selectors.md`）。

### 3-1. 調整紀錄

- 同日 Terris：「可以寬一點，不要那麼長的按鈕」→ 卡片從細長 pill 改為最寬 50rem 的圓角卡、頭像放大到 3rem、標題 1.125rem；CTA 手機版不再滿版。
  第一次調整時手機版三個元素擠成一列、文字被壓成直排，已補 `_content` 在 small 斷點 `flex-basis:100%` 修正（本機模擬確認）。
- 同日 Terris：「可以更寬，後面的 gradient 自己動，稍微有點 animation」，並提供 bencho.dev 參考 → `max-width` 50rem → 64rem；新增 `_aura` 網格漸層層＋IX3 `i-5bfa934a` 無限漂移。第一版幅度（xPercent -7、rotation 5°）在模擬中幾乎看不出來，調大為 -12／8° 並放慢到 10 秒。
- 同日 Terris：「整體可以不要那麼長嗎？」→ 64rem 讓文字和按鈕中間空出一大段。改為桌機 `width:auto`、`_content` 不再 `flex-grow`，卡片收在內容寬度（模擬約 700px）；手機維持滿版。
  回頭看，前一輪的「寬一點」比較接近「更有份量／更高」，不是「更長」。
- 同日提供五種 hover 比較頁（A 目前版／B 3D 傾斜／C 頭像散開／D 箭頭穿越／E 漸層湧起），Terris 選 **C＋E**，並要求「漸層散開更明顯」。
  因 `_aura` 已被無限漂移的 IX3 佔用 transform，hover 若再縮放同一元素會互相覆蓋，所以另建 `_glow` 層專供 hover。光暈第一版濃度（teal 50%）在模擬中差異不夠，調到 65%／55%／90%。
  移除白光掃過（`_shine` 元素與 class）與頭像波浪。
