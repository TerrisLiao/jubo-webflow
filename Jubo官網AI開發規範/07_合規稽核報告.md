## 四、⚠️ 雙底線 BEM 寫法（43 個）

Client-First 的雙底線代表**兩層資料夾**（`folder_subfolder_element`），不是 BEM 的修飾符。以下 class 用了 BEM 邏輯：

### 10-1. ⚠️ 更正：本報告先前的一項判斷是錯的

先前依據「只查 Desktop 斷點」的資料，宣稱 `jp3-section` 與 `jp3-container`
「沒有響應式、手機版會破版」。**這是錯的，實測後撤回。**

| Class | 實際斷點設定 |
|---|---|
| `jp3-section` | base `8rem` ／ `small` **`5rem`** |
| `jp3-container` | base `calc(100% - 4rem)` ／ `medium` **`3rem`** ／ `small` **`2rem`** |

兩個都有響應式。唯一真正的差異是 `jp3-section` **少了平板（medium）那一階**
（991px 時維持 8rem，Client-First 的 `padding-section-large` 會是 6rem），
以及手機是 5rem 而非 CF 的 4rem。**屬於數值差異，不是破版。**

成因與教訓見 `00_AI工作守則.md` §6-7。

### 10-4. AI Orb 技術選型已定案（2026-08-19）

四種做法實測後 **決定使用 Three.js**。完整比較、實測踩到的坑、以及可執行的四方對照檔，
見 [`09_GSAP動畫與互動規範.md`](09_GSAP動畫與互動規範.md) §10-0-1 與
[`custom-code/poc/ai-orb-compare.html`](../custom-code/poc/ai-orb-compare.html)。

重點結論：

- **Three.js** — AI Orb 主視覺（CSS 做不出有機變形的輪廓）
- **CSS** — 環境光暈、陪襯
- **Lottie** — 圖示／loading／插畫，**不做主視覺**（沒有可靠的 blur／glow，狀態切換是硬跳影格）
- **Rive** — 先不導入，理由具體：**AI Agent 無法產生也無法修改 `.riv`**
- **狀態機一律留在程式碼**，不可放進 `.riv` 或 Lottie 檔

**效能驗證方式**：不做預先的抽象跑分。**每個實際動態做完之後，由 Terris 在真機上實測**，
掉幀再依 `09_GSAP動畫與互動規範.md` §10-6-1 的守則調整（降 pixelRatio、減粒子、手機改 CSS fallback）。
