# 全站 Schema（JSON-LD）檢查 — 2026-10-13

對照基準：`11_AEO稽核與優化計畫.md` 的 A1–A8、P2-B、P2-C、P3-B。

## 檢查方法

- **線上版**：抓 `sitemap.xml` 的 138 個網址，137 頁抓回 HTML。逐頁解析 `application/ld+json`，用程式檢查以下項目：
  - 假評分；
  - 相對網址；
  - 空字串；
  - 沒有 name 的 Person；
  - FAQ 是否出現在頁面上；
  - `@id` 參照是否有定義。
- **Webflow 草稿版**：用 MCP 讀回有問題的頁面與三個 CMS template，確認草稿是否已經修好、只是還沒發布。
- 程式與原始結果放在 scratchpad（`schema_audit/audit.py`、`result.json`），未進 git。

## 🔴 嚴重

### 1. 新聞頁 NewsArticle 全部是空的（新發現，54/54 頁）

線上每一篇新聞的 schema 都長這樣：

```json
"headline": "", "description": "", "datePublished": "", "dateModified": "",
"articleBody": "", "articleSection": "", "image": "", "url": "/news/"
```

- **原因**：新聞 template（`69f82ba2…d696`）的 schema 存成「物件」格式（`jsonLdSchema`）。客戶案例和功能介紹 template 存成「原始字串」格式（`rawJsonLdSchema`），動態欄位都正常帶入。
  - 新聞 template 最後更新時間是 2026-10-05 04:18，跟同一批頁面相同，研判是那次批次更新時被轉成物件格式，CMS 綁定因此失效。
  - 8/31 的稽核時這份 schema 還是正常的（稽核文件「需要更正的稽核錯誤」一節）。
- **影響**：79 篇新聞中，有 54 篇在 sitemap 裡。這些頁面等於對搜尋引擎和 AI 宣告「沒有標題、沒有日期、沒有內容」，比完全沒有 schema 更糟。
- **修法**：用原始字串格式重寫 template，照客戶案例 template 的寫法。網址同時改為絕對網址。

- **建議**：改用首頁同一張 logo（`…69f92fb3b1e42e2e1d20a6bb_Frame-1.png`）。

### CMS template：3 個，API 無法寫入，改成 Designer 手動貼上

- 用 API 寫入時被拒（400 "schema markup must be valid JSON"）：動態欄位語法 `{{wf …\} }}` 裡的 `\}` 不是合法 JSON。
- 原本能正常輸出的 template，都是在 Designer 裡貼的原始字串。新聞 template 被 API 改成物件格式之後，動態欄位就失效了。
- 客戶案例與功能介紹 template **沒有用 API 動**，避免重蹈新聞 template 的覆轍。
- 可直接貼上的版本與步驟放在 `custom-code/schema-templates/`（含 README）。已用程式模擬欄位帶入，確認輸出是合法 JSON。
- **待辦**：Terris（或有 Designer 權限的人）把三份貼進 Page Settings，Publish 後抓線上 HTML 驗證。
- **規範**：CMS template 的 schema 一律在 Designer 手動貼，不要用 API／MCP 寫入。（repo 內沒有 `06_Webflow實作陷阱.md`，這條規範先記在這裡與 `custom-code/schema-templates/README.md`。）
