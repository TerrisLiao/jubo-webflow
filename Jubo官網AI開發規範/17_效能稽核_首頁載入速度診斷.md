# 17_效能稽核：首頁載入速度診斷

- 建立日期：2026-09-03
- 對象：`https://www.jubo-health.com/`（首頁）
- 起因：回報官網載入明顯偏慢，且無痕視窗同樣慢（排除本地快取／擴充套件因素）

## 驗證限制（先讀）

本次診斷以 HTTP 層實測完成，**不是**真實瀏覽器 Lighthouse 跑分：

- 量測機房位於 **AWS us-east-1（維吉尼亞）**，不是台灣。以下所有秒數皆為**最佳情況**；台灣使用者對非 CDN 主機的延遲約為此處的 2–3 倍。
- 本環境的 Chromium 無法穿過 egress proxy（`ERR_CONNECTION_RESET`），因此**沒有實測的 FCP / LCP / TBT / CLS 數字**。
- 相關結論凡屬推估者，下文均標記為「推估」。
- 建議由台灣端補跑 PageSpeed Insights / WebPageTest（Taipei node）取得真實 Core Web Vitals，再據以複驗。

## 結論摘要

HTML 本身不慢（Cloudflare 邊緣快取命中，TTFB 約 0.20s）。**慢在子資源，主因集中在 `slater.app`。**

| # | 問題 | 嚴重度 | 修復難度 |
|---|---|---|---|
| 1 | slater.app 回 `no-store`，且無 CDN、位於美東 | 高 | 低—中 |
| 2 | `<head>` 有 3 支 render-blocking script | 高 | 低 |
| 3 | body 有 10 支 blocking script，未壓縮約 500 KB | 中—高 | 低 |
| 4 | Swiper（約 170 KB）疑似首頁未使用 | 中 | 低 |
| 5 | 主 CSS 322 KB（brotli 55 KB） | 中 | 中 |
| 6 | 圖片未優化，最大單張 841 KB PNG | 中 | 低 |
| 7 | HTML 534 KB，含 79 個 inline SVG | 中 | 中 |
| 8 | 裸網域 301 跳轉不被快取 | 低 | 低 |

## 1. slater.app 是最大單一元凶

首頁載入兩個 slater 資源：

| 資源 | 位置 | 阻塞 | 大小 |
|---|---|---|---|
| `https://slater.app/20018/60294.css` | `<head>` | **render-blocking CSS** | 17.9 KB（gzip 3.6 KB） |
| `https://slater.app/20018/60292.js` | `<body>` | blocking script | 92.9 KB（gzip 19.3 KB） |

實測 response header：

```
cache-control: no-store
pragma: no-cache
via: 1.1 Caddy
```

- **`no-store` 代表瀏覽器完全不得快取。** 每一次瀏覽、每一次換頁，這兩個檔都要重新從遠端抓。這正好解釋「無痕視窗一樣慢」——因為一般視窗本來也沒有快取可用。
- `slater.app` 解析到 `44.202.1.154`（AWS us-east-1，維吉尼亞），前端是單台 Caddy，**沒有 CDN、沒有亞洲節點**。
- 從美東量測：`tls: 0.40s`、`ttfb: 0.45s`。台灣端推估單趟 0.8–1.2s。
- 由於 60294.css 是 `<head>` 中的 blocking stylesheet，**首次繪製必須等這支從維吉尼亞回來的檔案**。頁面在此之前是空白。

對照 Webflow 自家 CDN（同一頁的主 CSS）：

```
cache-control: public, max-age=31536000, immutable
cf-cache-status: HIT
age: 250543
```

差距非常明顯。

### 建議
1. **最有效**：把 60292.js / 60294.css 的內容搬進 Webflow（Site Settings 的 Custom Code，或 Webflow 託管的 JS asset）。Webflow 資源走 `cdn.prod.website-files.com`，有 Cloudflare 邊緣快取與 `immutable`，台灣端可直接命中在地節點。
2. 若要保留 Slater 的編輯流程：確認 Slater 方案是否支援輸出到自有 CDN／可快取端點；`no-store` 是 Slater 免費／開發模式的典型行為。
3. 過渡作法（改善有限，仍值得做）：把 `60294.css` 改為非阻塞載入，或把其中「首屏必要」的規則抽出來 inline 到 `<head>`。

## 2. `<head>` 有 3 支 render-blocking script

| 腳本 | 屬性 | 大小 |
|---|---|---|
| `ajax.googleapis.com/.../webfont.js` | **無 defer/async** | 13.2 KB |
| `cdn.jsdelivr.net/npm/lenis@1.1.13/...` | **無 defer/async** | 13.5 KB |
| `.../@flowbase-co/boosters-countup@1.0.0/...` | **無 defer/async** | 2.2 KB |

這三支會直接卡住 HTML parser。其中 `webfont.js` 問題最大：它只是為了載 Poppins 5 個字重，卻造成三段**序列**往返：

```
webfont.js (ajax.googleapis.com)
  → fonts.googleapis.com/css   （JS 執行後才發出）
    → fonts.gstatic.com/*.woff2
```

文字要到第三段回來才會用正確字體渲染。

### 建議
- 移除 `webfont.js`，改用 Webflow 內建的 Google Fonts 設定，或直接在 `<head>` 放 `<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Poppins:wght@300..700&display=swap">`。`display=swap` 可避免文字被隱藏。
- `lenis` 與 `countup` 加上 `defer`。兩者都不影響首屏內容。
- 補充：CSS 中的 `Noto Sans TC` 沒有對應 `@font-face`，實際走系統字（PingFang TC / 微軟正黑體）。這點是好的，維持現狀即可，不要改成從 Google Fonts 載中文字體（中文字體檔非常大）。

## 3. `<body>` 有 10 支 blocking script

依 DOM 順序，全部無 `defer`／`async`：

| 腳本 | 未壓縮大小 |
|---|---|
| jquery-3.5.1.min.js | 89.5 KB |
| webflow.schunk × 2 + webflow.*.js | — |
| gsap.min.js | 72.9 KB |
| ScrollTrigger.min.js | 44.6 KB |
| Draggable.min.js | 35.8 KB |
| InertiaPlugin.min.js | 7.3 KB |
| swiper-bundle.min.js | **155.3 KB** |
| slater.app/60292.js | 92.9 KB |

合計約 500 KB 未壓縮 JS，全部要下載 + parse + execute 才能互動。

### 建議
- 逐支確認首頁是否真的需要。`Draggable` + `InertiaPlugin`（43 KB）通常只有拖曳型輪播才需要。
- 能加 `defer` 的都加上（注意 slater.js 依賴 gsap，順序需一併調整）。

## 4. Swiper 疑似首頁未使用

首頁載入 `swiper-bundle.min.js`（155.3 KB）+ `swiper-bundle.min.css`（14.6 KB），共約 170 KB。

但實測 HTML：**`swiper-slide` 出現 0 次**。

若首頁的輪播是用 GSAP 或 Webflow 原生 Slider 實作，這 170 KB 是純浪費。

### 建議
確認 Swiper 的實際使用頁面，改為只在需要的頁面載入（Webflow 的 Page Settings → Custom Code），不要放在 Site-wide。

## 5. 主 CSS 322 KB

`jubo-health.webflow.shared.328eedf86.min.css` = 322,853 bytes（brotli 後 55 KB）。

快取設定良好（`immutable`，`cf-cache-status: HIT`），首次訪問仍是 render-blocking 的 55 KB。以 Webflow 站而言偏大，通常代表 Client-First 未使用的 class 累積。

### 建議
中期處理。搭配 `06_自訂Class完整清單.md` 與 `07_合規稽核報告.md` 做一次未使用 class 清理。**依 CLAUDE.md，刪除任何 class 前必須先查全站使用、Slater、IX2 與 Component。**

## 6. 圖片

- 不重複來源圖 54 張，最大變體加總 **3.06 MB**（含所有 srcset 變體則為 4.59 MB，瀏覽器實際只取其一）。
- 51 個 `<img>` 中 37 張 `lazy`、14 張 `eager` — lazy loading 設定是好的。

問題最大的幾張：

| 大小 | 檔案 |
|---|---|
| **841.5 KB** | `69f844f17a076a7f0ee47ce5_cases-3.png` |
| 353.4 KB | `6a7549a3ec269e2d87ad09a6_未命名設計.webp` |
| 342.1 KB | `6a112274eb37217428c40139_三三分享會-官網宣傳圖-1200x800.png` |
| 216.9 KB | `6a11227e6d8984fcaa9e00f7_DSC_0595-scaled.jpeg` |
| 172.1 KB | `6a11223f86f678134db1c98f_簽約儀式照片_1-scaled.jpeg` |
| 159.4 KB | `6a11226c5738e8a9c5856e4e_fb_智齡-e1768370217399.jpeg` |

觀察：檔名帶 double-encoding（`%25E4%25B8...`）與 `-scaled` 後綴的，是從 WordPress 搬遷過來、未重新優化的素材，集中在 CMS（`/news` 類）圖片。

### 建議
- `cases-3.png` 841 KB 轉 WebP，預期可降到 100–150 KB。這是投報率最高的單項。
- CMS 圖片建立上傳規範：一律 WebP、長邊 ≤ 1600px、單檔 ≤ 200 KB。
- 首屏 hero（`hero-img.webp`, 68 KB）大小合理，但可考慮加 `<link rel="preload" as="image">` 改善 LCP。

## 7. HTML 534 KB

- 原始 534,415 bytes，gzip 後 181,673 bytes。
- 元素數約 2,040（含 908 個 `div`）。
- **79 個 inline SVG，含 208 個 `<path>`、84 個 `<stop>` 漸層節點。**
- 20 段 inline `<style>`，合計 25.5 KB。
- CMS：3 個 `w-dyn-list`、30 個 `w-dyn-item`（數量合理，不是問題）。

inline SVG 無法被瀏覽器快取，每次換頁都重新傳輸一次。漸層定義特別佔空間。

### 建議
把重複使用的 SVG（logo、圖示）改為 Webflow Asset 的 `<img src="*.svg">`，即可享有 CDN 快取。這需要在 Designer 逐一調整，建議排在 slater.app 與 script 修正之後。

## 8. 裸網域 301 跳轉不被快取

```
GET https://jubo-health.com/
→ 301 https://www.jubo-health.com/
   cf-cache-status: BYPASS
   cache-control: private
```

使用者若輸入不帶 www 的網址（或舊連結、名片、QR code），會多付一次完整的 DNS + TCP + TLS + 回源往返（實測 TTFB 0.45s，台灣端推估 0.8s+），且**每次都付**，因為 Cloudflare 對此跳轉是 BYPASS。

### 建議
在 Cloudflare 設定 Redirect Rule（或 Page Rule）處理 apex → www，讓跳轉在邊緣完成並可快取。這需要 Cloudflare 後台權限。

---

## 9. 第三方主機數量

頁面共牽涉 12 個 host：

```
ajax.googleapis.com          d3e54v103j8qbb.cloudfront.net
cdn.jsdelivr.net             fonts.googleapis.com
cdn.prod.website-files.com   fonts.gstatic.com
slater.app                   www.googletagmanager.com
```

每個都需要獨立的 DNS + TCP + TLS 建立。`<head>` 目前只對 `cdn.prod.website-files.com`、`fonts.googleapis.com`、`fonts.gstatic.com` 做了 `preconnect`。

### 建議
補上 `<link rel="preconnect" href="https://slater.app" crossorigin>` 與 `cdn.jsdelivr.net`。這是治標，但成本極低。

## 建議執行順序

**第一波（影響最大、風險最低）**
1. 把 slater.app 的 JS/CSS 搬到 Webflow 託管 —— 解決 `no-store` + 跨洋 + render-blocking 三個問題
2. 移除 `webfont.js`，改用 `fonts.googleapis.com` + `display=swap`
3. `lenis` / `countup` 加 `defer`
4. `cases-3.png` 841 KB 轉 WebP

**第二波**

5. 確認 Swiper 是否首頁需要，不需要就移出 site-wide（省 170 KB）
6. 檢查 GSAP Draggable / InertiaPlugin 必要性（省 43 KB）
7. 補 preconnect
8. Cloudflare apex → www 跳轉規則

**第三波（需要較多 Designer 工時）**

9. 未使用 class 清理，縮小主 CSS
10. inline SVG 改為 Asset 引用
11. CMS 圖片上傳規範與既有素材批次優化
