## 5. 已知的工具限制（供後續 agent 參考）

- `data_element_tool > set_style` 與 `data_element_builder` 的 `set_style`，**遇到「同時存在 global 定義與 combo 定義」的 class 名稱會回報 `styles not found`**（例：`login-hub_heading` 同時有 `.login-hub_heading` 與 `.heading-style-h1.login-hub_heading`）。
- 可行的替代路徑：`data_whtml_builder` 傳 `<div class="a b">`，它能正確對應到既有 class（本次 hero、卡片外層、grid 都是這樣重建的）。既有元素要換 class，就用 whtml 新建一個、把子元素 `move_element` 過去、再刪掉舊的。
- `data_element_tool > set_attributes` 對「剛用 whtml 建好的元素」會回 MPS `[Conflict]`；改成在 whtml 的 HTML 字串裡直接寫屬性即可。

## 7. Navbar 分區調整（utility 群組）

- 日期：2026-09-03
- 起因：Terris 參考國外 B2B SaaS（Salesforce）的做法 —— **潛在客戶的主導覽** 與
  **既有客戶入口／轉換動作** 在 header 上做空間區隔，不要排成同一串。
- 狀態：**已修改，未 Publish。**

### 問題

§6 把「登入」直接插在「公司」後面，`nav-link_wrapper` 是 `gap: 1.75rem` 的均勻 flex，
「預約諮詢」按鈕也吃同一個 gap。結果「登入」讀起來就是第六個導覽項目，沒有分區。

### 做法

在 `.nav-link_wrapper` 末端新增 `.nav-utility_wrapper`（element id
`67873837-4720-755b-a6df-c4335ad83f57`），把「登入」與 `Glass Button` 一起移進去：

```
.nav-link_wrapper  (flex, justify-content: flex-end, gap 1.75rem)
├ 找到適合你的方案 ⌄  產品 ⌄  資源 ⌄  客戶  公司
└ .nav-utility_wrapper  (flex, align-items: center, gap 1rem, margin-left 1.5rem)
   ├ 登入（.nav-link）
   └ Glass Button「預約諮詢」
```

間距關係：公司 ↔ 登入 = `1.75rem + 1.5rem = 3.25rem`；登入 ↔ 按鈕 = `1rem`。
內外比約 3.25:1，兩者明顯讀成一組。

新增 class 一個：`.nav-utility_wrapper`（folder `nav-utility` ／ element `wrapper`，
命名對齊既有的 `nav-link_wrapper`）。只有 flex 與間距，**不含任何顏色**。

### 刻意沒做的

- **沒有沿用站上既有的 `.nav-divider`。** 它屬於 Webflow 範本殘留那一批
  （`Navbar Logo Left`、`Nav Menu Two`、`Nav Dropdown*` 同一家族），用 `15px` 硬寫間距
  與硬寫 `hsla()` 色碼，主導覽沒在用。沿用等於把範本殘留拉回現役。
- **沒有加人形 icon。** 站上 nav 的 icon 都是 HTML Embed（`.nav-icon`），多一個 embed
  多一個維護點；中文「登入」兩字辨識度already足夠。先看間距效果，需要再加。
- 手機抽屜不需要處理：它本來就是垂直清單，「登入」已經落在「公司」與底部 CTA 之間，
  自然就在同一區。

### 驗證

- 元素樹確認：`nav-link_wrapper` 現在是 5 個 `.nav-link` ＋ 1 個 `.nav-utility_wrapper`，
  群組內依序是「登入」與 `Glass Button`。
- **驗證限制：改完後 Webflow Designer 連線中斷，未取得改後截圖。** 間距是依
  `nav-link_wrapper` 的 `1.75rem` gap 推算，實際視覺需在 Designer 目視確認。
- `.nav-link_wrapper` 在 `medium`（≤991px）是 `display: none`，桌機列整段隱藏，
  因此新 wrapper 不需要額外的 RWD 覆寫。
