## 1. 問題診斷（實際讀回，非推測）

前一版的內容結構（Hero → 多層防護 → 隱私 → AI → 資源 → CTA）方向沒有錯，
**壞在執行層：它沒有用站上的設計系統，而是在旁邊另外長了一套。**

| 項目 | 實測 | 違反 |
|---|---|---|
| 頁面專屬 class | 一頁新建 **95 個** `security-*` class | 鐵律 1「先找、再用、最後才建」 |
| 手打色碼 | `#173044`、`#7f6cbc`、`rgba(64,68,112,.1)`、`rgba(71,58,119,.12)` … | 鐵律 4「顏色一律用 Variables」 |
| 自畫裝飾 | `security-network_ring-one/two/three`、`security-bento_orbit`、`security-hero_glow-left/right`、`security-bento_cloud-shape` | 15 §3「禁止假產品 UI、抽象 AI 圖」 |
| 孤兒 class | `section_security-bento`、`-bento-v2`、`security-check_*` 等前幾版殘留仍在 Style Manager | 00 §5 收工檢查表 |
| 新漸層 | Terris 要求「新創一個 gradient」，實際做法是把 `linear-gradient(135deg,#f1edff,#eaf7ff,#fff2e8)` 直接寫死在 `section_security-hero` 上，**沒有進 Variables** | 鐵律 4 |
| 文案 | `security-bento_lead` 寫著「參照日本頁的 Bento 邏輯…」——**內部工作註記外洩到正式文案** | — |
| 文案 | 「資安事件通報窗口／公開管道確認後提供」——placeholder 留在頁面上 | — |
| 裝飾字 | 卡片上放 `ID`、`↔`、`24/7`、`03` 等無意義符號 | — |

> 核心判斷：**這不是「再調一下樣式」的問題，是整頁的視覺語言來源錯了。**
> 站上其他繁中正式頁（`/products/residential-care`、`/company`）的區塊長相是
> `section-header_wrapper` ＋ `Section Tag` ＋ `3col-grid` ＋ 純文字排版，
> 不是 bento 玻璃卡。元件清單也寫明「不要讓整頁每一段都變成卡片或玻璃」。

## 2. 強調色決策

Terris 已指示：**不可用 `primary/Ocean`（`#175e5e`）當強調色，Ocean 平常只用在 Footer。**

本次提出三個選項，Terris 選擇 **「沿用既有漸層家族，不新增變數」**。

依據：站上本來就有一套 teal → blue → purple 的漸層語言，**不需要另外發明**。

| 既有資產 | 值 |
|---|---|
| `.gradient-headline` | `linear-gradient(90deg, var(--primary--accent), var(--gradient--announce-bar-purple))` ＋ `background-clip:text` |
| `.cases-gradient` | `linear-gradient(0deg, hsla(231,100%,61.57%,.2), hsla(184,100%,37.65%,.1) 50%, transparent)` |
| `.marquee__advanced__p.is-gradient` | `linear-gradient(90deg, hsla(184,100%,37.65%,1), #b15dff)` |

→ 本頁強調一律走 `.gradient-headline`（H1 內行內 span）＋ `Page Gradient BG` 元件背景。
**Jubo Variables 維持 33 個，本次沒有新增、修改或刪除任何變數。**

### Mobbin 參考（已逐張看過版面）

| 來源 | 借用的佈局邏輯 |

| [Mixpanel](https://mobbin.com/sites/sections/4d22bd9a-625d-4eb8-98de-cf47e909d4d1) | eyebrow → 大標 → lead → 三張「視覺面板 + 標題 + 說明」；把資安講成產品功能 |

## 4. Class 使用與清理

- v1 已刪除前一版留下的 **83 個** 孤兒 `security-*` class（詳見 v1 紀錄，內容保留於 git 歷史）。
- v2 **新建 1 個** class：`section_security-bento`（只有 `position: relative`）。
- v2 直接沿用日本頁既有的 `jp-security_*` 系列，未新建平行版本。

> ⚠️ **耦合風險（需知道）**：繁中資安頁與日本頁現在共用同一組 `jp-security_*` class。
> 之後若有人調整日本頁的便當樣式，**這一頁會跟著變**。
> 這是「刻意共用同一個模組」的取捨；若要解耦，要把這組 class 改名成中性的 `security-bento_*` 並同步改兩頁，
> 屬於另一件工作，不在本次範圍。

另：日本頁便當帶有 `data-jp-reveal` / `data-jp-delay` / `data-jp-tilt` 進場動畫屬性，
**本次未複製**——沒有把握那段 JS 是全站掛載還是只綁日本頁，先不引入。便當目前是靜態的。

### ⚠️ 驗證限制

**仍未取得畫布快照。** `element_snapshot_tool` 需要 Designer 分頁在前景，目前取不到，
因此以下為依 CSS 推論、**未目視確認**：

- 便當 grid 自帶 `max-width: 64rem`，比其他段的 `container-large`（82rem）窄。
  日本頁本來就是這個關係，但在繁中頁與上下段並排時是否顯得縮腰，要看過才知道。
- `jp-security_media` 用負 margin ＋ `calc(100% + 3.3rem)` 做出血，
  與 `jp-security_bento` 的 `padding: 0` 搭配。日本頁正常，繁中頁沿用同一組值理論上相同。
- `jp-security_layer-copy` 在 desktop 是 `display: none`，四層卡只顯示編號與標題；
  平板以下是否顯示需確認。
- 第 3~5 段仍是連續三個 `3col-grid`，便當之後的節奏是否仍偏單調。
