1. **去背**：從四邊 flood fill，**不是**全域把白色變透明。

## 3-3. 標章白邊修正與 ISO 去底（2026-09-21 第四輪）

Terris 回報兩件事：

1. 「你的 hippa pdpa pipeda 沒有切乾淨 現在都有白邊」
2. 「同時 iso 不能有底色 現在的設計跟其他的不太搭」

### 問題一：白邊

**成因。** 原檔是 lossy webp，反鋸齒邊緣像素落在 200–240 之間，
上一輪的去背是**容差 18 的二值 flood fill**，這些中間值判不進背景就整片留著不透明，
再經單色化那一段「近白保留白色」的規則，全部變成純白 —— 形成一圈白邊。

**我自己的驗證也有問題。** 上一輪只在淺灰／白底預覽，白邊在白底上根本看不見，
是 Terris 在藍色漸層底上才發現。**淺底預覽不能當作去背驗證。**

**修正做法：邊緣羽化 alpha matte，不是二值判斷。**

```
BGT = 140
從四邊 flood fill，只走「min(r,g,b) > BGT」的連通區 → 這塊是背景
背景區內：  alpha = clamp((255 - min(r,g,b)) / (255 - BGT))   RGB 一律壓成 #49515E
            （純白 → alpha 0，接近門檻 → alpha 1，中間值平滑過渡）
背景區外：  沿用原本保留白色鏤空的映射（t = clamp((min-170)/55)）
```

一樣是從四邊 flood fill，所以 PDPA 的白色內圈、ISO 的白色鏤空字仍然保得住。

**驗證。** 重新在**藍色漸層（Terris 截圖的那個底）／深色 `#22344a`／品牌 teal／150px 放大／
頁面實際 `#f8f8f8`** 五種底上檢查；另外做程式檢查：
統計「可見但半透明且接近白」的像素數（真正的白色鏤空是完全不透明，不會被算進去）——
7 張全部 **fringe = 0**。

### 問題二：ISO 有底色

原授權檔是**藍底白色鏤空**的方塊。上一輪單色化只是把藍底換成 `#49515E`，
所以整排裡只有三枚 ISO 帶著實心色塊，跟旁邊透明底的 HIPAA／PDPA／PIPEDA／Bluetooth 不同家族。

**做法：把鏤空反轉過來。** 以紅色通道量測覆蓋率
（藍底 `rgb(20,97,163)` → 白 `255`，紅通道落差最大，最穩），
白色圖形轉成 `#49515E` 不透明，藍底轉成全透明。號碼改用 Liberation Sans Bold
（Helvetica metric clone，與 ISO 字標同屬 grotesque）排在地球下方，同色。

> 供檔的 ISO 原檔四邊帶 1–2px 的淺色邊框（第 0 列、第 0–1 行），
> 會讓 alpha bbox 裁切失效，處理前先切掉 3px。

結果：**透明底、`#49515E` 平塗的地球 ＋ 號碼**，與其他六枚同一個視覺家族。
這是同一枚授權標章的單色呈現，不是重新設計。

## 4. 2026-09-21 第五輪：以四層防護圖為核心重建

### 為什麼又重來

前四輪都在修表面（換模組、換版型、修標章白邊），但沒有人回頭確認**頁面上寫的東西有沒有依據**。
文案是在沒有事實來源的情況下寫的，所以通篇是「協助確保」「依服務範圍確認適用條件」
「以最新文件及雙方合約為準」這種避責句型。

Terris 指示：先去 M365 盤點 Jubo 實際的資安作為（特別是「如何防滲透」），
再重新規劃 structure 與逐段 layout，核心要有一張**四層防護圖**。

### 受眾與揭露深度（Terris 定案）

| 項目 | 決定 |
|---|---|
| 受眾 | **潛在客戶**——看懂資安水準，不是給稽核員逐項比對 |
| 揭露深度 | **控制面向層級**；證書編號、效期、演算法版本、廠商名**一律不上頁** |
| 數字來源 | 2026 手冊草稿版 |
| HIPAA 寫法 | 「通過 SGS 之符合性驗證」 |
| 認證列 | 先維持現狀七枚 |
| Hero CTA | 保留「認識智齡科技」→ `/company` |

### M365 盤點：可寫上頁的事實

來源：`資安回覆` SharePoint 頁（陳依伶建立／林靜瑤維護，2026-07-02）、
`台中仁愛之家資安疑問 26.0804_V2.docx`、`Jubo 現階段資安防護內容.docx`、

查證到的：RBAC 最低權限、全公司 MFA、M365 企業單一簽入、密碼 12 字元不可重複前 3 次、
5 次失敗鎖 15 分鐘、TLS 1.2+、AES-256、Cloudflare WAF／DDoS、異常登入偵測、
Checkmarx SAST＋SCA、每次更版原始碼檢測、每週弱點檢修、年度第三方滲透測試
（中芯數據，114.06 報告無惡意程式與隱藏通道）、日誌保存 6 個月、正式／測試／開發環境隔離、
前端敏感欄位遮蔽、8 小時通報／24 工作小時處置（`ISMS-P-004` v2.0）、
每日備份 RPO 12 小時、年度還原演練、數位長暨資安長 李泓其、ISMS／PIMS 三層文件體系、
資安小學堂教育訓練、GCP 主機。

**頁面上只寫收斂後的控制面向**，上述括號內的演算法、廠商、報告編號都不上頁。

### 🔴 上線前必須先解決（與版面無關）

1. **ISO 27001 證書 2026-10-02 到期**，M365 內找不到 2026 年換證證書（最新只到 2025-08 的第二次監督審核通過證明）。需跟 Starry（林靜瑤）確認。

3. **Bluetooth 資料夾內只有 Bluetooth SIG 商標規範與 logo 原檔**，沒有 Declaration ID 或測試報告。

> Terris 表示這兩枚自行確認。**三件事確認完成前不得 Publish。**

### 四層防護圖怎麼做的

**用 div 疊出來，不用圖檔**——可響應、可改字、有語意、不必另送一張新圖審核，
也不碰 15 §5「不得生成假認證／假 UI」與鐵律 4「不得用 HTML Embed 畫版面」。

四層由外而內收窄置中，最底下是「照護資料」，形狀本身就在說資料被包在最裡面。

| 層 | 名稱 | 底色（全部綁 Variables） |
|---|---|---|
| 01 | 裝置與身分 | `--neutral--white` |
| 02 | 傳輸加密 | `--gradient--teal` |
| 03 | 應用與雲端環境 | `--gradient--light-teal` |
| 04 | 資料保存 | `--primary--accent` |
| core | 照護資料 | `--neutral--black`，白字 |

寬度：desktop 100／88／76／64%，core 52%；medium 100／92／84／76%，core 68%；
**small 與 tiny 四層一律 100%**——手機做寬度漸縮會讓最內層窄到放不下字，改由底色深淺表示層次。
Radius 依 15 §5：desktop 2rem／tablet 1.25rem／mobile 1rem。

### 踩到的坑

- `row-gap` **不接受 length 變數**（`Property row-gap does not support setting a variable of type length`）。
  站上既有 grid 都是用 `grid-row-gap`，改成 grid 版面就過了。
- `_3col-grid` 在 main／medium／small 都是三欄，**只有 tiny 才降成一欄**。
  不是「手機自動變單欄」，排三欄以上內容時要自己確認。
- `create_style` 的參數是 `parent_style_names`（陣列）、`style_name`、`breakpoint_id`、
  `properties: [{property_name, property_value | variable_as_value}]`——與直覺的 camelCase 都不同。
