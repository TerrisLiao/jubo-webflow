## 1. 為什麼要換

| | IX2（現況） | IX3 |
|---|---|---|
| **MCP 可讀寫** | ❌ 完全讀不到。要挖 631 KB 的 published JS 才看得到動畫定義 | ✅ Headless，`list/get/create/update/delete_interaction` |
| **`prefers-reduced-motion`** | ❌ 沒有這個概念 | ✅ `conditionalPlayback` 一行設定 |
| **斷點條件** | 只能「播／不播」 | ✅ 可設 `skip-to-end` |
| **目標選擇** | class／子元素 | ✅ `wf:class`、`wf:inst`、`wf:selector`、`wf:attribute` ＋ `filterContext` 關係 |
| **緩動** | 少數幾種 | ✅ 31 種預設 ＋ 進階（elastic／back／steps／customBounce／自訂貝茲） |
| **錯開（stagger）** | 要逐元素複製動作 | ✅ 原生 `{each, amount, axis, from, grid}` |
| **文字拆字** | ❌ 目前靠 Slater 自訂 JS | ✅ 原生 `splitText`（chars／words／lines） |
| **捲動** | 基本 | ✅ 完整 ScrollTrigger（`start`／`end`／`scrub`／`pin`） |

> 實例：2026-09-22 的卡片 hover 回歸，就是因為 IX2 的定義 MCP 讀不到，
> 必須反推 published JS 才找到 `a-15` 的 `selector: ".single-news_cover-img"`。
> 換成 IX3 後，這類相依性在動工前就查得到。

## 4.5　試點結果（2026-09-22，`/news` 新聞卡片 hover）

**狀態：staging 已驗證通過，正式站未動。** 互動 id `i-b019b836`。

### 🔴 發現 A：`wf:class` 目標是「全站選取」，不是「被觸發的那一個」

第一版用 `wf:class` 指向 `.news-card_cover-img`，並加上
`filterContext: {relationship:"within", filterBy:["wf:class",[卡片 class id]]}`。

**實測：hover 第 1 張卡，53 張卡的封面全部一起縮放。**
`filterContext` 是靜態結構過濾（「所有位於某 class 內的元素」），
**不是相對於觸發元素**。

唯一能限縮到單一實例的是 `wf:trigger-only`（動畫目標＝觸發元素本身）。

### 🔴 發現 B：78 / 96 個 IX2 動畫用的是 API 無法等價重現的模式

解析線上 IX2 定義，統計 `useEventTarget`：

| IX2 target 型態 | 數量 | IX3 API |
|---|---|---|
| **`CHILDREN`**（動畫「觸發元素底下帶某 class 的子元素」） | **78** | ❌ 無對應 |
| `SIBLINGS` | 17 | ⚠️ 或許可用 `next/prev-sibling-of` |
| `PARENT` | 5 | ✅ `wf:trigger-only-parent` |
| 事件目標本身（`!0`） | 5 | ✅ `wf:trigger-only` |

> **✅ 2026-09-22 已在 Designer 確認：不是 API 的限制，是 IX3 本身沒有這個能力。**
>
> Designer 的 Target 下拉選單完整選項為：
>
> | Designer 選項 | API 對應 |
> |---|---|
> | **Trigger element**（"Target the element that triggered the interaction"） | `wf:trigger-only` |
> | Element | `wf:inst` |
> | Class | `wf:class` |
> | Attribute | `wf:attribute` |
> | Custom selector | `wf:selector` |
> | Any element | `wf:any-element` |
>
> **沒有 Children / Descendants / Nested。** 面板與 API 的能力完全一致
> （API 另有面板未列出的 `wf:trigger-only-parent`，反而多一個）。
>
> **結論：那 78 個動畫無法忠實重現，必須重新設計。**
> 設計準則見 `21_Jubo動效準則_IX3.md`。
>
> 由此推出的硬規則：**凡是要「只動被觸發的那一個」，被動畫的元素必須就是觸發元素。**

### 🔴 發現 C：split hover 形式每次載入只會播一次（官方文件沒寫）

官方文件把 split 形式（兩個 `wf:hover` 觸發器 ＋ `assignedGroupId`）
寫成「the panel writes for separate hover out」，並示範 `control: "play"`。

**實測：同一張卡連續 hover 進出 4 次，只有第 1 次有動作。**

```
第 1 次  hover 進 → y=-3   離開 → y=0
第 2 次  hover 進 → y=0    ← 沒反應
第 3 次  hover 進 → y=0    ← 沒反應
第 4 次  hover 進 → y=0    ← 沒反應
```

原因是文件自己寫的：`play` is inert once the timeline has reached its end。
而改成 `restart` 會被主機擋下：

```
Trigger "wf:hover" must use control "play" when the interaction has
multiple action groups; the Designer offers only Play there.
```

**✅ 正解：改用 role 形式** —— 單一 `wf:hover` 觸發器
＋ `pluginConfig: {multiTimeline: true}`，兩個 timeline 各標
`triggerMetadata: {role: "mouseEnter"}` / `{role: "mouseLeave"}`。
改完後 4 / 4 次全部正常。

> ⚠️ 這個坑非常隱蔽：寫入成功、讀回正確、第一次 hover 也正常，
> **只有連續 hover 第二次才會發現**。所有 hover 類的遷移都要測「重複觸發」。

### ✅ 發現 D：`prefers-reduced-motion` 完全可用

實測開啟 reduced-motion 後，IX3 的位移完全不觸發，
而同一張卡上 IX2 的標題淡化照樣執行 —— 正好證明了 IX2 沒有這層保護。

### 採用的設計：不重現舊效果，改成符合站上規範的版本

站上 Agent Instruction `jubo-web-visual-system.md` §13 明訂：

> Hover 以輕微透明度或 **1–2px 位移**為主；**避免大幅 Scale**、Bounce 或過度 Spring。

原本的 `TRANSFORM_SCALE 1.03` 其實**不符合這條規範**。試點因此不重現它，
改為規範建議的作法：

| | 舊（IX2） | 新（IX3） |
|---|---|---|
| 效果 | 封面圖縮放 1.03× | **整張卡上浮 3px** |
| 觸發區 | 整張卡 | 整張卡（相同） |
| 目標 | `CHILDREN` + class | `wf:trigger-only` |
| 時長／緩動 | 350ms outQuad | 250ms `ease: 5`（power2.out） |
| reduced-motion | 無保護 | `dont-animate` |
| 標題淡化 0.6 | IX2 | IX2（暫留，見下） |

`y` 用固定 px 而非 `yPercent`：這是固定的小位移，用百分比會隨卡片高度變化。

**版面位移實測：grid top 0 → 0，無 reflow**（`transform` 不影響 layout）。

### 尚未完成

標題淡化（`.news-card_headline-inner-wrap` opacity 0.6）**仍由 IX2 驅動**。
因為 IX2 的事件 `e-78`/`e-79` 無法用 API 刪除，若 IX3 也做同一件事會變成兩套系統
同時驅動同一個屬性。完整切換需要在 Designer 裡移除 IX2 的事件。

## 5. 動工前必讀的 IX3 陷阱（官方文件明載）

1. **「寫入成功不代表會動」** —— `A successful create is not proof it played.`
   每一個都必須發布驗證。2026-09-22 的 srcset 誤判就是同一類錯誤。
2. **Initial Appearance（靜止樣式）API 設不了** —— 淡入類效果要改用
   `tt: 2` 帶起始值，或先用 style API 設 class 的 `opacity`。
3. **未知的 key 會被靜默丟掉，不報錯** —— 例如 `easing` 不是合法 key（正確是 `ease`），
   寫錯就變成「預設緩動」而且沒有任何錯誤訊息。
4. **`ease` 只吃整數索引**，不吃 `"power1.out"` 這種字串。
5. **opacity 放在 `wf:transform`**，不是 `wf:style`。
6. **duration 的裸數字是「秒」** —— `400` 是 6 分 40 秒，不是 400ms。
7. **上限**：5 timelines／20 triggers／200 actions per timeline／20 targets per action。
   已存在的超額互動 Designer 讀得到但 MCP 改不動。
8. **批次失敗不一致**：MCP 參數層失敗會整批放棄且不寫入；host 層失敗只影響該項。
   所以形狀有風險的 payload 要單獨送。

## 6. 驗證限制

- 383 / 96 這兩個數字來自解析線上 published JS，是**已發布版本**的狀態；
  Designer 裡若有未發布的互動不會反映在內。
- 重複實作的判定是依「標題去掉尾端編號後相同」分組，
  **合併前仍須逐一比對實際 action 內容**（可能有人改過其中一份的數值）。
- Navbar / Dropdown 那 6 個尚未確認 Designer 手動重建的可行性。
